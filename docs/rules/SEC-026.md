## 1. Catalog claim (verbatim from `rules.yaml`)

```yaml
- id: SEC-026
  name: "Duplicate SPN Registered"
  description: >-
    The same non-host Service Principal Name is registered on multiple accounts.
    Duplicate SPNs cause Kerberos authentication failures and can indicate
    misconfiguration or an attacker staging a Kerberoast relay. Common built-in
    host aliases such as HOST, RestrictedKrbHost, kadmin, and krbtgt are excluded.
  severity: High
  category: CredentialTheft
  remediation: >-
    Remove the duplicate SPN from all but one account using setspn -D.
    Investigate whether the duplication was intentional.
  mitre: T1558.003
  tags: ["kerberos", "spn", "duplicate", "misconfiguration"]
```

Source: `src/SecureAD.Core/Findings/Rules/rules.yaml` lines 190–199.

## 2. Intended detection (plain English)

A finding must be raised, at `High` severity, **once per owner of a
duplicated SPN**, whenever the same non-host SPN value appears on the
`target` column of `dim_delegation` (`delegation_type = 'SPN'`) for two
or more distinct AD objects. The attack scenario is twofold: (a) a
misconfigured duplicate breaks Kerberos for both accounts (KDC may
issue a TGS for the wrong principal); (b) an attacker who can write
SPNs registers the SPN of a high-value service onto a controlled
account to receive Kerberos service tickets bound to the attacker's
key. Common host-alias SPNs (`HOST/...`, `RestrictedKrbHost/...`,
`kadmin/...`) and the `krbtgt` account itself are excluded because
they are expected to be duplicated across DCs / KDCs in a healthy
forest. The cross-domain DC short-name aliasing case (a DC's short
SPN advertised both at its DC OU object and at the legacy
`CN=Computers` shadow object in a parent / child domain) is also
suppressed.

### 3.1 Effective SQL (copied from code, after this card's fixes)

```sql
SELECT d.target AS spn,
       GROUP_CONCAT(o.distinguished_name, '|') AS owners,
       GROUP_CONCAT(COALESCE(o.sid, ''), '|') AS sids,
       GROUP_CONCAT(o.object_guid, '|') AS guids,
       GROUP_CONCAT(o.object_class, '|') AS classes,
       GROUP_CONCAT(o.domain_fqdn, '|') AS domains,
       COUNT(DISTINCT d.object_guid) AS owner_count
FROM dim_delegation d
INNER JOIN dim_object o ON d.object_guid = o.object_guid
WHERE d.delegation_type = 'SPN'
  AND d.target NOT LIKE 'HOST/%'
  AND d.target NOT LIKE 'RestrictedKrbHost/%'
  AND d.target NOT LIKE 'kadmin/%'
  AND d.target NOT LIKE 'krbtgt/%'
  AND (o.sid IS NULL OR o.sid NOT LIKE '%-502')
GROUP BY d.target
HAVING COUNT(DISTINCT d.object_guid) > 1
ORDER BY owner_count DESC
```

Notes:

- SQLite `LIKE` is **case-insensitive for ASCII** by default (no
  `PRAGMA case_sensitive_like` is set anywhere in the codebase, confirmed
  by grep), so the host-prefix exclusions match both `HOST/` and
  `host/`.
- The `(o.sid IS NULL OR o.sid NOT LIKE '%-502')` clause is the
  result of `[IMP-NULL-SID]` (new tag) — without the `IS NULL` guard,
  SQLite's three-valued logic silently dropped NULL-SID owners.
  Resolved in this card.
- The `d.target NOT LIKE 'krbtgt/%'` clause is the result of
  `[IMP-CAT-WORDING]` — the catalog described `krbtgt` as a
  host-alias exclusion, but the previous SQL only excluded the
  krbtgt **account** by SID `-502`. Now both are excluded, which
  matches the documented intent. Resolved in this card.

### 3.2 Post-SQL filters (in C#)

- `if (IsDomainControllerRootComputerAliasDuplicate(spn, dnList, classList, domainList)) continue;` — suppresses the well-known case where a DC's short SPN (e.g., `TERMSRV/BADC`) appears on both the DC computer object in `OU=Domain Controllers` of one domain and a legacy alias under `CN=Computers` of a parent / child domain. Requires **all** of: every owner is `object_class = 'computer'`, every owner's leading CN equals the short SPN host, at least one owner DN contains `,OU=Domain Controllers,`, at least one owner DN contains `,CN=Computers,`, and the distinct `domain_fqdn` set has more than one entry. Any owner that is not a computer or whose CN ≠ host short-circuits the whole exclusion via early `return false`.
- Per-owner `Detail` derivation: `otherOwners = string.Join(", ", dnList.Where((_, idx) => idx != i).Take(3))`, then if `ownerCount > 4`: append `(+{ownerCount - 4} more)`. The "Also on" list shows at most 3 other DNs; **when there are exactly 4 owners, no overflow note is appended even though only 3 of the other 3 are shown** — borderline. (Re-reading: with 4 owners, each finding's `otherOwners` has 3 entries — all 3 of "the others" are shown. So the conditional is correct.)
- Per-owner `FindingKey = "SEC-026|{ownerSid}|{ownerGuid}"`. Does **not** include the SPN. Collapses if the same owner participates in two distinct duplicate-SPN groups (e.g., `MSSQLSvc/sqlA` and `MSSQLSvc/sqlB` both duplicated, both involving owner A). Captured in `[IMP-KEY-COLLAPSE]` under §12.

## 5. Exclusions (and the reason each is correct)

| Exclusion | Mechanism | Justification |
| --- | --- | --- |
| `HOST/` SPN prefix | SQL `d.target NOT LIKE 'HOST/%'` | Every domain-joined computer ships with `HOST/<short>` and `HOST/<fqdn>` SPNs; duplication is the steady state. |
| `RestrictedKrbHost/` SPN prefix | SQL `d.target NOT LIKE 'RestrictedKrbHost/%'` | Same as HOST — auto-registered by Netlogon for constrained-delegation host alias. |
| `kadmin/` SPN prefix | SQL `d.target NOT LIKE 'kadmin/%'` | Cross-realm Kerberos administration; duplication is expected across MIT-realm trusts. |
| Owners whose SID ends in `-502` (krbtgt) | SQL `o.sid NOT LIKE '%-502'` | The krbtgt account participates in TGS issuance and may carry duplicate-looking SPNs as part of trust bookkeeping. |
| Single-owner SPNs | SQL `HAVING COUNT(DISTINCT d.object_guid) > 1` | The rule definition requires ≥2 owners. |
| DC short-name alias duplicate (DC OU + root `CN=Computers` in a different domain) | Post-SQL `IsDomainControllerRootComputerAliasDuplicate` | Legacy cross-domain shadow object pattern; not actionable. |
| `krbtgt/` SPN prefix | SQL `d.target NOT LIKE 'krbtgt/%'` (added by this card per `[IMP-CAT-WORDING]`) | Cross-realm `krbtgt/REALM` SPNs are expected duplicates across trust topologies, and the catalog wording already lists `krbtgt` as an expected exclusion. |
| (Implicit, not enforced) Tombstoned owner (`is_deleted = 1`) | _none_ | `[IMP-DEL-OBJ]` in §12. |
| (Implicit, not enforced) Non-account `object_class` owner (group, OU, container) | _none_ | The schema doesn't restrict; in practice only `user` / `computer` / `*ManagedServiceAccount` carry SPNs. `[IMP-TGT-CLASS]` in §12. |

## 9. Output assertions (`Detail` and `ContextJson`)

The finding produced must include:

- `RuleId == "SEC-026"`
- `Severity == High`
- `SubjectSid` = owner SID (empty string when the owner's `o.sid` is NULL after coalescing — but in practice the owner is filtered out of the SQL upstream by the `NOT LIKE '%-502'` NULL behaviour, so this is unreachable; documented for completeness)
- `TargetKind == "object_guid"`
- `TargetId` = owner object GUID (`D` format)
- `SourceEdgeId == null`, `SourcePathId == null` (delegation finding, no edge/path provenance)
- `FindingKey == "SEC-026|{SubjectSid}|{TargetId}"`
- `Detail == "Duplicate SPN '{spn}' registered on {ownerCount} accounts. Also on: {otherOwners}"` where `otherOwners` is a comma-separated DN list of at most 3 other owners, optionally suffixed with `(+{ownerCount - 4} more)` when `ownerCount > 4`.
- `ContextJson` non-null and contains:
  - `"evidence_type": "delegation"`
  - `"delegation_type": "DuplicateSPN"`
  - `"spn": "<SPN value>"`
  - `"owner_count": <int>`
  - `"object_dn": "<this owner's DN>"`
  - `"other_owners": "<comma-separated DN list with optional overflow>"`
  - `"object_guid": "<GUID in D format>"`

Note: SEC-026's `CreateDelegationFinding` does **not** carry a
`rule_id` key inside `ContextJson` (the helper passes the dictionary
through `JsonSerializer.Serialize` directly, without injecting any
reserved field — unlike the control-edge path which uses an
`EdgeFindingContext` record with a `RuleId` property). This is a small
asymmetry with SEC-024 / SEC-025 but is internally consistent with
SEC-020 / SEC-021 / SEC-022 / SEC-023. Tracked under `[IMP-CTX-RULEID]`
(new tag) in §13.

## 12. Defects / deferred items

1. `[IMP-CAT-WORDING]` — **Resolved in this card.** The catalog
   wording lists *"Common built-in host aliases such as HOST,
   RestrictedKrbHost, kadmin, and krbtgt are excluded"*, treating
   `krbtgt` as an SPN-prefix exclusion. The previous SQL implemented
   it as an owner-account exclusion only (`o.sid NOT LIKE '%-502'`).
   The SQL was tightened to also include
   `AND d.target NOT LIKE 'krbtgt/%'`, which is the canonical
   cross-realm exclusion behavior and matches the catalog wording.
   Pinned by `WhenDuplicateKrbtgtPrefixSpnOnTwoUsers_ThenSEC026DoesNotFire`.

2. `[IMP-NULL-SID]` — **Resolved in this card.** The previous SQL
   `o.sid NOT LIKE '%-502'` evaluated to NULL when `o.sid IS NULL`,
   and SQLite's three-valued logic treats NULL as false in the
   WHERE clause. Net effect: owners with no captured SID were
   silently excluded from SEC-026, which was not a deliberate
   exclusion. The clause was rewritten to
   `(o.sid IS NULL OR o.sid NOT LIKE '%-502')`. Pinned by
   `WhenAllOwnersHaveNullSid_ThenSEC026Fires`. The cross-cutting
   audit recommendation (sweep every `LIKE` / `NOT LIKE` against a
   nullable column) remains open and is tracked in §13.

3. `[IMP-KEY-COLLAPSE]` — **Accepted-with-known-limitation.**
   `FindingKey = "SEC-026|{ownerSid}|{ownerGuid}"` does not
   discriminate by SPN. If the same owner participates in two
   distinct duplicate-SPN groups, only one finding survives the
   `fact_finding` `INSERT OR IGNORE`. Pinned by
   `WhenOwnerHasDuplicateSpnsInTwoGroups_ThenSEC026CollapsesViaFindingKey`
   so the regression is detectable if the helper is changed.
   Fix deferred to the cross-cutting `[IMP-KEY-COLLAPSE]` workstream
   that already covers SEC-012 / SEC-014 / SEC-020.

4. `[IMP-DEL-OBJ]` — **Accepted-with-known-limitation.** SQL joins
   `dim_object` without filtering `is_deleted = 1`. Tombstoned
   owners with stale duplicate SPNs still fire. Deferred to the
   cross-cutting `[IMP-DEL-OBJ]` workstream.

5. `[IMP-TGT-CLASS]` — **RESOLVED.** The SQL now constrains
   `o.object_class IN ('user', 'computer', 'msDS-GroupManagedServiceAccount',
   'msDS-ManagedServiceAccount')` so a duplicate SPN owned by a non-account
   class (group / OU) no longer fires. Pinned by
   `WhenDuplicateSpnOwnedByNonAccountClass_ThenSEC026DoesNotFire`.

6. `[IMP-DN-ENRICH]` — **Accepted-with-known-limitation.** `Detail`
   and `ContextJson` carry DNs and SIDs but no `sam_account_name` /
   `display_name`. Operator remediation typically goes through
   `setspn -D` keyed on `sAMAccountName`, not DN. Deferred to the
   cross-cutting `[IMP-DN-ENRICH]` workstream.

7. `[IMP-PARITY-TEST]` — **Accepted-with-known-limitation.** No
   per-rule severity / MITRE / tag parity assertion exists for
   SEC-026 in `RuleCatalogParityTests`. Deferred to the
   cross-cutting `[IMP-PARITY-TEST]` workstream.

## 13. Improvement suggestions (not blocking)

1. `[IMP-CTX-RULEID]` — `ContextJson` produced by
   `CreateDelegationFinding` does not embed `"rule_id"` as a top-level
   field (unlike the control-edge / escalation-path helpers which
   serialize a typed record with a `RuleId` property). Consumers
   reading `ContextJson` in isolation lose the rule provenance.
   Suggested resolution: change `CreateDelegationFinding` (or
   `CreateContextJson`) to inject `"rule_id"` as a reserved field,
   matching the edge / path shape. Affects every Kerberos-family
   rule that emits via the delegation helper (SEC-020, SEC-021,
   SEC-022, SEC-023, SEC-026).

2. `[IMP-NULL-SID]` (cross-cutting sweep) — `[IMP-NULL-SID]` was
   resolved for SEC-026 in §12. The same NULL-handling pattern may
   exist in other evaluators that compare against a nullable column
   via `LIKE` / `NOT LIKE`. Audit candidate: every SQL in
   `src/SecureAD.Infrastructure/Findings/Evaluators/*.cs` that
   references `dim_object.sid` with `LIKE` (`fact_control_edge.source_sid`
   is `NOT NULL` in schema, so the issue is isolated to nullable
   columns).
