## 1. Catalog claim (verbatim from `rules.yaml`)

```yaml
- id: SEC-091
  name: "LAPS Missing on Computer"
  description: >-
    A computer is missing its tier-appropriate LAPS deployment. Modern OS (Server 2019+/Windows 11)
    should have Windows LAPS (msLAPS-PasswordExpirationTime). Server 2016 should have Legacy LAPS
    (ms-Mcs-AdmPwdExpirationTime).
  severity: Medium
  category: ConfigurationHygiene
  remediation: >-
    Deploy the appropriate LAPS solution. For Server 2019+ and Windows 11, deploy Windows LAPS via GPO.
    For Server 2016, deploy Legacy LAPS (AdmPwd.E or Microsoft LAPS client).
  mitre: T1078.002
  tags: ["laps", "configuration", "hygiene"]
```

Source: `src/SecureAD.Core/Findings/Rules/rules.yaml` lines 434–443.

## 2. Intended detection (plain English)

For every non-deleted, non-DC computer in the snapshot, decide whether the appropriate LAPS variant is deployed:

- **Modern OS** (Server 2019/2022/2025 or Windows 11) → must have **Windows LAPS** (`msLAPS-PasswordExpirationTime`).
- **Legacy OS** (Server 2016) → must have **Legacy LAPS** (`ms-Mcs-AdmPwdExpirationTime`).
- **Unknown / unclassified OS** (blank, Server 2012, Windows 10, etc.) → fire only when **no LAPS variant at all** is configured.

Domain Controllers are excluded by design — they use the krbtgt/DSRM machinery, not LAPS. Severity is `Medium` because absence is a configuration gap, not an active credential exposure (T1078.002 — _Valid Accounts: Domain Accounts_, since unmanaged local admins risk shared-password lateral movement).

## 4. Effective SQL executed

### Main path (when `dim_object.operating_system` column exists)

```sql
SELECT o.object_guid, o.distinguished_name, o.operating_system, o.domain_fqdn,
       dw.object_guid AS has_windows, dl.object_guid AS has_legacy
FROM dim_object o
LEFT JOIN dim_delegation dw ON o.object_guid = dw.object_guid
                           AND dw.delegation_type = 'LapsEnabled' AND dw.target = 'Windows'
LEFT JOIN dim_delegation dl ON o.object_guid = dl.object_guid
                           AND dl.delegation_type = 'LapsEnabled' AND dl.target = 'Legacy'
WHERE o.object_class = 'computer' AND o.is_deleted = 0
  AND o.distinguished_name NOT LIKE '%,OU=Domain Controllers,%'
ORDER BY o.domain_fqdn, o.distinguished_name
```

Per-row decision (in C#):

| OS classification | Condition | Action |
| --- | --- | --- |
| Modern | `os.Contains("2019")` OR `"2022"` OR `"2025"` OR `"Windows 11"` | If `!has_windows` → fire (`laps_type = "Windows"`) |
| Legacy | `os.Contains("2016")` | If `!has_legacy` → fire (`laps_type = "Legacy"`) |
| Unknown | none of the above | If `!has_windows && !has_legacy` → fire (`laps_type = "Any"`) |

### Legacy-schema fallback (when `operating_system` column missing)

```sql
SELECT o.object_guid, o.distinguished_name, o.domain_fqdn,
       dl.object_guid AS has_any_laps
FROM dim_object o
LEFT JOIN dim_delegation dl ON o.object_guid = dl.object_guid
                          AND dl.delegation_type = 'LapsEnabled'
WHERE o.object_class = 'computer' AND o.is_deleted = 0
  AND o.distinguished_name NOT LIKE '%,OU=Domain Controllers,%'
  AND dl.object_guid IS NULL
ORDER BY o.domain_fqdn, o.distinguished_name
```

## 5. Defects discovered and fixed this session

| # | Description | Defect risk | Fix |
| --- | --- | --- | --- |
| 1 | Main path DC exclusion relied on `o.sam_account_name NOT IN (SELECT sam FROM DCs)`. A DC whose `sam_account_name` is `NULL` (rare but possible during capture) bypasses the subquery and fires as a false positive. | False positive on DCs. | Replaced the sam-account-name subquery with a direct DN match (`distinguished_name NOT LIKE '%,OU=Domain Controllers,%'`), matching the legacy fallback's exclusion. |
| 2 | Legacy-schema fallback was missing `o.is_deleted = 0`; tombstones (`CN=...,CN=Deleted Objects,...`) would have surfaced as "LAPS missing". | False positive on tombstones. | Added `o.is_deleted = 0` to the legacy fallback WHERE clause. |

Both fixes are verified by the new tests in §7.

## 10. Severity rationale

`Medium` matches `rules.yaml` and is loaded via `BuiltInRules.ById["SEC-091"].DefaultSeverity` through `RuleEvaluatorHelpers.SeverityOf`. The finding is a configuration gap, not an active credential disclosure (that is SEC-090). Promoting to `High` would risk drowning operators in noise during initial LAPS rollouts.

## 11. MITRE mapping

`T1078.002` — _Valid Accounts: Domain Accounts_. The connection is indirect: without LAPS, local administrator accounts share passwords across machines, enabling reuse of compromised credentials as "valid accounts" for lateral movement. The mapping is defensible but loose; see §13 `[IMP-MITRE-FIT]`.

## 13. New cross-cutting items captured this session

- `[IMP-OS-CLASSIFIER]` — The modern/legacy OS classification is a `string.Contains` over English-only substrings (`"2016"`, `"2019"`, `"2022"`, `"2025"`, `"Windows 11"`). Misses lowercase strings, localized OS names, and emerging OSes (Server 2026+). Centralize as a typed classifier with a versioned table.
- `[IMP-DC-DETECT]` (existing tag) — DC exclusion is still a hard-coded `LIKE '%,OU=Domain Controllers,%'`. Brittle if customers move DCs to a non-default OU. Should be a snapshot-derived DC SID set (UAC `SERVER_TRUST_ACCOUNT` bit or primary-group RID 516) per the existing taxonomy entry. Applies here too even after fixing the NULL-sam bug.
- `[IMP-EMPTY-SUBJECT]` — `FindingKey` for per-object findings is `"SEC-091||{guid}"` (literal empty middle segment). Functional but visually odd; consider an explicit format for per-object findings (`"SEC-091|object|{guid}"`).
- `[IMP-MITRE-FIT]` — Mapping to `T1078.002` is loose for a configuration-hygiene rule. Audit for tighter / supplemental MITRE mapping or move to category-level tagging.
- `[IMP-LEGACY-FALLBACK]` — The legacy-schema branch exists "in case the `operating_system` column is missing" but has no integration test exercising it; only the main path is covered. Worth either backfilling a test or removing the fallback once all callers guarantee the column.
- `[IMP-PARITY-TEST]` (existing tag) — SEC-091 has 20 tests; sibling LAPS rules (SEC-090, SEC-092) have far fewer per-branch tests. Establish a per-rule minimum test set checklist.
