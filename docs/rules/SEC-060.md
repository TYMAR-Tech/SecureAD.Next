## 1. Catalog claim (verbatim from `rules.yaml`)

```yaml
- id: SEC-060
  name: "Broad Principal with Dangerous Write Access"
  description: >-
    Everyone, Authenticated Users, Domain Users, or BUILTIN\\Users has takeover-class write access to an object.
  severity: High
  category: ConfigurationHygiene
  remediation: >-
    Remove excessive permissions from Everyone/Authenticated Users.
  tags: ["everyone", "excessive-permissions"]
```

Source: `src/SecureAD.Core/Findings/Rules/rules.yaml` lines 283–291.

## 2. Intended detection (plain English)

Fire one finding per `fact_control_edge` row where the source SID is a broad,
unauthenticated, or all-domain-users principal and the control type grants
takeover-class write access to the target object. Deny ACEs that have been
fully cancelled by upstream allows are excluded. Severity is `High` by default,
elevated to `Critical` when the target object is Tier-0 (Domain Admins,
Enterprise Admins, Schema Admins, Domain Controllers, AdminSDHolder, or the
domain root itself).

### 3.1 SQL

```sql
SELECT e.source_sid, e.target_object_guid, e.control_type,
       o.distinguished_name, e.edge_id, o.sid AS target_sid
FROM fact_control_edge e
INNER JOIN dim_object o ON e.target_object_guid = o.object_guid
WHERE e.deny_cancelled = 0
  AND e.control_type IN (
        'WriteDacl', 'WriteOwner', 'Owns',
        'GenericAll', 'GenericWrite', 'WriteAllProperties',
        'CreateChild', 'DeleteChild'
      )
  AND (e.source_sid IN ('S-1-1-0', 'S-1-5-11', 'S-1-5-7', 'S-1-5-32-545')
       OR e.source_sid LIKE '%-513')
ORDER BY e.source_sid, e.target_object_guid, e.control_type
```

### 3.2 Per-row work

For every matching row the evaluator:

1. Resolves a friendly name for the source SID via `ResolveBroadSidName`.
2. Decides severity: `Critical` when `IsBroadSidTargetTierZero(targetSid, targetDn)` is true; otherwise `High`.
3. Calls `CreateEdgeFinding("SEC-060", ...)` which:
   - Builds `FindingKey = "SEC-060|{source_sid}|{target_guid}"` — **`control_type` is NOT in the key**.
   - Serializes the strongly-typed `EdgeFindingContext` (with classification flags) into `ContextJson`.

## 5. Exclusions (and the reason each is correct)

| Exclusion | Mechanism | Justification |
| --- | --- | --- |
| Read-class ACEs (`ReadProperty`, `ListContents`, …) | SQL `control_type IN (...)` whitelist | The rule is about takeover-class write access; broad-read findings are out of scope. |
| Deny ACEs cancelled by an upstream allow | `e.deny_cancelled = 0` | A deny ACE that survives the merge means the dangerous grant was neutralized; emitting it would be a false positive. |
| Non-broad principals | `source_sid IN (...)` OR `LIKE '%-513'` | Per-principal misconfiguration findings (SEC-001..SEC-006) cover those cases with a richer privilege context. |
| Target with no `dim_object` row | `INNER JOIN dim_object` | Without a target identity the finding cannot be remediated; treat as `Objects` coverage gap. |

Not excluded (intentionally subject to review):

- **BUILTIN\Administrators (`S-1-5-32-544`)** — correctly **not** in the broad-source list (it is privileged-by-design; covered by `PrivilegedSystemSids`).
- **Anonymous Logon (`S-1-5-7`)** — included in the SQL even though the catalog text does not enumerate it. The code is right; the catalog wording omits it. `[IMP-CAT-WORDING]`.
- **Cross-domain RID -513** — `LIKE '%-513'` matches Domain Users in any domain, including foreign domains; correct because cross-domain ACEs from broad principals are still risky.

## 8. Edge cases considered

| # | Scenario | Resolution |
| --- | --- | --- |
| E1 | Deny ACE / `deny_cancelled = 1` | Excluded via SQL filter (N3). |
| E2 | Inherited ACE | Out of scope at this layer — `fact_control_edge` is already the post-resolution graph; inheritance was already collapsed upstream. |
| E3 | Deleted target object (`is_deleted = 1`) | Not filtered. `[IMP-DEL-OBJ]`. Accepted: a tombstoned target may still hold the dangerous ACE until cleanup. |
| E4 | Multiple matching edges for same (sid, target) | `FindingKey` omits `control_type`, so `INSERT OR IGNORE` collapses to one finding per (sid, target). Pinned by `WhenBroadSidHasMultipleControlTypesOnSameTarget_ThenSEC060CollapsesToOne`. `[IMP-KEY-COLLAPSE]`. |
| E5 | Coverage incomplete for required module | Coverage map = `[Objects, SecurityDescriptors, ControlEdges]`; missing any yields zero findings, not false positives. |
| E6 | Cross-domain principal | `LIKE '%-513'` matches across domains; correct (P13). |
| E7 | Broad SID enumeration drift | SQL whitelist (`S-1-1-0`, `S-1-5-11`, `S-1-5-7`, `S-1-5-32-545`, RID-513) and `RuleEvaluatorHelpers.BroadSids` (`S-1-1-0`, `S-1-5-11`, `S-1-5-7`) are partially redundant. Domain Users and BUILTIN\Users are intentionally **only** in the SQL list — not in `BroadSids` — because `BroadSids` participates in the principal-classification flag and Domain Users / BUILTIN\Users are not "pre-auth" broad. Accepted; documented as `[IMP-BROAD-DRIFT]`. |
| E8 | Privileged-by-membership (transitive DA/EA) non-RID SID | Out of scope — those are not broad principals. |
| E9 | Tier-0 detection on DNS zone nodes that start `DC=` | `IsBroadSidTargetTierZero` excludes them via the `,CN=` ancestor test (N2). |
| E10 | BUILTIN\Administrators in SQL whitelist | Intentionally absent — it is privileged-by-design, not broad. |
| E11 | Target SID present but `dim_object` row missing | Cannot happen with INNER JOIN; tested via N5. |

## 9. Output assertions (`Detail` and `ContextJson`)

The finding produced must include:

- `RuleId == "SEC-060"`
- `Severity == High` (or `Critical` when target is Tier-0)
- `SubjectSid` = exact broad SID from the edge (`S-1-1-0`, `S-1-5-11`, `S-1-5-7`, `S-1-5-32-545`, or `*-513`)
- `TargetKind == "object_guid"`
- `TargetId` = target `object_guid` (`D` format)
- `SourceEdgeId` populated (`fact_control_edge.edge_id`)
- `SourcePathId` is `null`
- `FindingKey == "SEC-060|{SubjectSid}|{TargetId}"` (no `control_type` in key — see E4)
- `Detail` contains: friendly name (`Everyone` / `Authenticated Users` / `Anonymous Logon` / `BUILTIN\Users` / `Domain Users`), `control_type`, and target DN or GUID
- `ContextJson` non-null and contains:
  - `rule_id == "SEC-060"`
  - `source_sid` = broad SID
  - `target_guid` = `TargetId`
  - `control_type` = the row's control type
  - `evidence_type == "control_edge"`
  - `source_is_broad_principal == true`

## 12. Defects / deferred items

1. `[IMP-CAT-WORDING]` — Catalog description enumerates four principals
   ("Everyone, Authenticated Users, Domain Users, or BUILTIN\\Users") but the
   SQL also includes **Anonymous Logon** (`S-1-5-7`). Code is correct; the
   catalog text should be updated to read `"Everyone, Anonymous Logon,
   Authenticated Users, Domain Users, or BUILTIN\\Users"`. Accepted as a
   cross-cutting catalog cleanup.

2. `[IMP-KEY-COLLAPSE]` — `FindingKey = "SEC-060|{sid}|{guid}"` omits
   `control_type`, so when one broad SID holds multiple takeover-class control
   types on the same target only the lexicographically-first persists. Pinned
   by `WhenBroadSidHasMultipleControlTypesOnSameTarget_ThenSEC060CollapsesToOne`.
   Same pattern accepted for SEC-012, SEC-014, SEC-020, SEC-026, SEC-040.

3. `[IMP-DEL-OBJ]` — No filter on `dim_object.is_deleted`. Tombstoned targets
   still produce findings until cleanup. Cross-cutting; accepted.

4. `[IMP-PARITY-TEST]` — `RuleCatalogParityTests` does not yet assert the
   `ContextJson` schema specific to SEC-060 (e.g., the
   `source_is_broad_principal` classification flag); covered by the shape
   test in §10. Accepted as a cross-cutting parity backlog item.

## 13. Improvement suggestions (not blocking)

1. `[IMP-BROAD-DRIFT]` — Two parallel "broad" lists exist:
   `RuleEvaluatorHelpers.BroadSids` (`S-1-1-0`, `S-1-5-11`, `S-1-5-7`) and the
   inline SQL whitelist here (adds `S-1-5-32-545` and `LIKE '%-513'`). The
   former drives classification flags; the latter drives SEC-060 firing.
   They will drift in opposite directions over time. Suggest extracting a
   single `BroadPrincipalCatalog` that exposes both an `IsBroad(sid)` test
   and a SQL-friendly enumeration. **New tag** — add to taxonomy.

2. `[IMP-CTRL-SCOPE]` — **RESOLVED.** The shared takeover/property-write
   control-type set is now centralized: `RuleEvaluatorHelpers.BroadPropertyWriteRights`
   (`{GenericAll, GenericWrite, WriteAllProperties}`) + `PropertyWriteEquivalents(specific)`
   back the widened property-write rules (SEC-006 / SEC-024 / SEC-025 / SEC-081), and
   SEC-014 keeps its own `WriteRbcdEquivalents`. SEC-060's own broad-write whitelist
   (`WriteDacl, WriteOwner, Owns, GenericAll, GenericWrite, WriteAllProperties,
   CreateChild, DeleteChild`) is a deliberately broader takeover set (it includes the
   DACL-pivot and child-object rights that the property-write helper excludes), so it
   stays inline by design rather than collapsing into the shared constant.

3. `[IMP-TGT-CLASS]` — The Tier-0 detection mixes SID-based and DN-based
   heuristics (`OU=Domain Controllers,`, `DC=...` prefix, `,CN=` ancestor
   exclusion). A more principled `TargetTier` resolver that consulted
   captured `dim_object.object_class` and a domain-root flag would be more
   robust and easier to extend per-domain. Cross-cutting.

4. `[IMP-DN-ENRICH]` — `Detail` falls back to the bare GUID when `targetDn`
   is null. SEC-060 already enforces a `dim_object` row via INNER JOIN, but
   the row may legitimately have a null DN at very early capture stages.
   Suggest substituting the target `sam_account_name` or `object_class`
   before the GUID fallback. Cross-cutting.
