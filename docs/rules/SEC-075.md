## 1. Catalog claim (verbatim from `rules.yaml`)

```yaml
- id: SEC-075
  name: "Path to Custom-Tier Target"
  description: >-
    A non-administrative principal has a privilege escalation path to a target classified via tier policy (user-defined high-value assets).
  severity: Medium
  category: PrivilegeEscalation
  remediation: >-
    Review and break the escalation path by removing control edges.
  mitre: T1078
  tags: ["escalation-path", "custom-tier"]
```

Source: `src/SecureAD.Core/Findings/Rules/rules.yaml` lines 368–377.

## 2. Intended detection (plain English)

Fire one finding per row in `fact_escalation_path` where:

- the **target** is classified `Custom` — i.e., `dim_asset_tier.tier =
  'Custom'` when the table is populated, or any target whose fallback
  RID classifier returns `"Custom"` (anything that is not RID 512,
  516, or 519) when the table is absent; and
- there is **no path-length constraint** (`minPathLength` and
  `maxPathLength` are both `null` at the dispatcher); and
- the **source** is not itself a well-known admin principal
  (`IsAdminSid` exclusion).

Severity is the catalog default `Medium` on **both** the tier-table and
fallback code paths. An earlier revision boosted the fallback path to
`High` for RIDs {500, 502, 518} via a `GetFallbackSeverity` /
`IsTierZeroFallbackSid` helper pair; `[IMP-FALLBACK-TIER]` **removed** both
helpers and aligned `ClassifyFallbackTier` with `StaticAssetTierClassifier`,
so those RIDs now classify as `Tier0` in fallback and route to SEC-070
(Critical) — they no longer surface as SEC-075 at all.

SEC-075 is the **catch-all** sibling of SEC-070..074 and shares the
same evaluator code path. Well-known Tier 0 / Tier 1 RIDs route to
SEC-070..074 via their dedicated tier strings (`Tier0`, `Tier0Shadow`,
`Tier1`) in **both** modes now that the fallback classifier is aligned;
only genuine `Custom`-tier targets land in SEC-075, always at `Medium`.

### 3.1 Effective SQL (copied from code)

Primary path (when `dim_asset_tier` exists):

```sql
SELECT p.path_id, p.source_sid, p.target_sid, p.path_length, p.path_detail, p.coverage_complete,
       sp.display_name AS source_name, tp.display_name AS target_name,
       att.reason AS tier_reason
FROM fact_escalation_path p
LEFT JOIN dim_principal sp ON p.source_sid = sp.sid
LEFT JOIN dim_principal tp ON p.target_sid = tp.sid
LEFT JOIN dim_asset_tier att ON p.target_sid = att.sid
WHERE COALESCE(att.tier, 'Tier2') = $tier
ORDER BY p.source_sid, p.target_sid, p.path_id
-- $tier = 'Custom'
```

Fallback path (when `dim_asset_tier` does not exist):

```sql
SELECT p.path_id, p.source_sid, p.target_sid, p.path_length, p.path_detail, p.coverage_complete,
       sp.display_name AS source_name, tp.display_name AS target_name
FROM fact_escalation_path p
LEFT JOIN dim_principal sp ON p.source_sid = sp.sid
LEFT JOIN dim_principal tp ON p.target_sid = tp.sid
WHERE 1 = 1
ORDER BY p.source_sid, p.target_sid, p.path_id
-- tier classification then applied per row via ClassifyFallbackTier
```

### 3.2 Post-SQL filters (in C#)

- `IsAdminSid(sourceSid) → skip` — exclude rows whose source SID is a
  well-known admin (RID 500, 502, 512, 516, 518, 519, 520, 521, 526,
  527 — `AdminRids` in `RuleEvaluatorHelpers.cs:27`) or a well-known
  privileged system SID. `BroadSids` are explicitly **not** treated as
  admins.
- Fallback path only: `ClassifyFallbackTier(targetSid) != "Custom" →
  skip` — drops rows whose target RID is 512 (`Tier0` → SEC-070/071),
  519 (`Tier0Shadow` → SEC-072), or 516 (`Tier1` → SEC-073/074).
  Every other RID — including 500, 502, 517, 518, 548, 549, 550, 551,
  553, 555, 557 — falls through to `"Custom"` and surfaces here.
- Fallback path only: severity is computed via
  the catalog `Severity.Medium` via `SeverityOf("SEC-075")` on both the
  tier-table and fallback code paths. `[IMP-FALLBACK-TIER]` removed the
  former `GetFallbackSeverity` boost and aligned `ClassifyFallbackTier`
  with `StaticAssetTierClassifier`, so Tier-0 RIDs (500 / 502 / 512 / 516 /
  518 / 519) now classify as `Tier0` in fallback and route to **SEC-070**,
  not SEC-075. SEC-075 fires only for `Custom`-tier targets, always at
  `Medium`. Pinned by `WhenFallbackPathToTierZeroRid_ThenSEC070FiresNotSEC075`
  and the `*_DoesNotFireInFallback` tests in this fixture.

## 5. Exclusions (and the reason each is correct)

| Exclusion | Mechanism | Justification |
| --- | --- | --- |
| Paths to non-Custom targets | `WHERE COALESCE(att.tier, 'Tier2') = 'Custom'` (primary) / `ClassifyFallbackTier(target) == "Custom"` (fallback) | SEC-075 is the catch-all bucket. Tier-0 / Tier-0-Shadow / Tier-1 targets surface as SEC-070..074. |
| Unclassified targets (tier-table mode) | `COALESCE(att.tier, 'Tier2') = 'Custom'` evaluates to `'Tier2' = 'Custom'` (false) for any target without a `dim_asset_tier` row | A target without a `dim_asset_tier` entry is **not** a "Custom HVT" — the policy author has not declared it high-value. Pinned by `WhenTargetHasNoAssetTierRow_ThenSEC075DoesNotFire`. |
| Admin sources | Post-SQL `IsAdminSid(sourceSid) → continue` | A path from `Domain Admins → ... → custom HVT` is normal admin lateral movement, not an escalation. Uses RID + well-known SID matching, never group-membership expansion (see E8). |
| Broad SIDs not excluded | `IsAdminSid` explicitly returns `false` for `BroadSids` (line 80) | A path from `Authenticated Users` to a Custom HVT is still a Medium escalation and must surface. |

Not excluded (intentionally subject to review):

- `coverage_complete = 0` rows — the rule still fires; the per-row flag
  flows through `CreatePathFinding` to `FindingV2.CoverageComplete`.
- Deleted (`is_deleted = 1`) source / target — `dim_object` is **not**
  joined; the path service is expected to drop tombstoned principals
  at capture time. Cross-cutting `[IMP-DEL-OBJ]`.
- Cross-domain paths — surface as-is.
- Very short paths (`path_length = 1`) and very long paths (`>= 10`) —
  no bound on path length for SEC-075 (the rule is intentionally
  unbounded).

- `RuleId == "SEC-075"`
- `Severity == Medium` for any `Custom` target on both the tier-table and

## 12. Defects / deferred items

> Tag each entry with an `[IMP-xxx]` code (see `docs/rules/IMPROVEMENTS.md`). Resolved items are kept for historical context and are intentionally untagged.

1. **Fallback classifier narrower than the tier table** `[IMP-FALLBACK-TIER]` —
   **RESOLVED** (see SEC-070 §12.1). `ClassifyFallbackTier` now delegates to
   `StaticAssetTierClassifier`, which returns `Tier2` (not `Custom`) for arbitrary
   RIDs and routes the well-known Tier-0 / Tier-1 RIDs to their proper rules. The
   former `GetFallbackSeverity` boost (which surfaced Tier-0 RIDs 500 / 502 / 518 as
   High SEC-075 findings) is removed — those now fire SEC-070 / SEC-071. **SEC-075
   therefore does not fire in fallback mode**: `Custom` is a policy-defined tier that
   requires a populated `dim_asset_tier` (covered by `EscalationPathTierFindingsTests`).
   The former fallback-Custom positives were converted to
   `WhenPathToArbitraryRidTarget_ThenSEC075DoesNotFireInFallback` and siblings.
   (Before the fix, `ClassifyFallbackTier` recognised only three RIDs and
   everything else — including Tier-0 500 / 502 / 518 and the full Tier-1 set —
   fell through to `"Custom"` and surfaced as SEC-075 in fallback, with a bespoke
   `GetFallbackSeverity` boost for the Tier-0 subset. Both the narrow classifier
   and the boost helper are now gone.)
