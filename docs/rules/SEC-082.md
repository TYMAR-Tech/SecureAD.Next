## 1. Catalog claim (verbatim from `rules.yaml`)

```yaml
- id: SEC-082
  name: "Unexpected Principal can Modify GPO via SYSVOL"
  description: >-
    A non-administrative principal has filesystem write access (write data, write DACL, write owner, or full control) on a Group Policy Object's SYSVOL policy folder. SYSVOL stores the actual policy files (Registry.pol, GptTmpl.inf) that domain-joined hosts apply, so write access there modifies effective policy regardless of the GPO's directory-object permissions.
  severity: Critical
  category: ConfigurationHygiene
  remediation: >-
    Remove write permissions on the GPO's SYSVOL folder (\\<domain>\SYSVOL\<domain>\Policies\{GUID}) unless the delegation is explicitly required and documented.
  mitre: T1484.001
  tags: ["gpo", "tier-zero", "configuration", "sysvol"]
```

## 2. Intended detection (plain English)

Fire when a non-admin principal holds a filesystem **write** right on a GPO's SYSVOL policy folder DACL. This is the second, ACL-independent modify path for a GPO: the directory object may be locked down, but whoever can write the on-disk `Registry.pol` / `GptTmpl.inf` files controls the effective policy applied to every targeted host. Complements SEC-080 (GPO modify via the directory-object ACL); SEC-080 emits a `also_writable_via_sysvol` union flag when the same GPO has a SYSVOL writer.

### 3.1 Effective SQL

```sql
SELECT a.trustee_sid, a.gpo_guid, gpo.distinguished_name,
       SUM(a.access_mask & $SysvolWriteMask) AS write_bits
FROM fact_sysvol_ace a
INNER JOIN dim_object gpo ON a.gpo_guid = gpo.object_guid
WHERE a.ace_type IN (0, 5)               -- AccessAllowed / AccessAllowedObject only
  AND (a.access_mask & $SysvolWriteMask) != 0
GROUP BY a.trustee_sid, a.gpo_guid, gpo.distinguished_name
ORDER BY a.trustee_sid, a.gpo_guid
```

`SysvolWriteMask = FILE_WRITE_DATA 0x2 | WRITE_DAC 0x40000 | WRITE_OWNER 0x80000 | GENERIC_WRITE 0x40000000 | GENERIC_ALL 0x10000000` (bits per winnt.h).

### 3.2 Post-SQL filters (C#)

1. `IsAdminSid(trusteeSid)` → skip well-known admin RIDs / privileged system SIDs.
2. Otherwise emit one finding per `(trustee, GPO)`.

## 5. Exclusions (and the reason each is correct)

| Exclusion | Mechanism | Justification |
| --- | --- | --- |
| Read-only / non-write ACEs | SQL `access_mask & SysvolWriteMask != 0` | Read does not let a principal alter policy files. |
| Deny ACEs | SQL `ace_type IN (0, 5)` (allow only) | A deny ACE grants no access. |
| Well-known admin trustees | `IsAdminSid(trusteeSid)` | Admins are expected to manage SYSVOL policy. |
| GPO not in `dim_object` | `INNER JOIN dim_object` | Without the directory object the finding cannot be attributed to a GPO. |
