## 2. Intended detection (plain English)

Fire one finding per principal that is a **direct** member of the built-in
`BUILTIN\Pre-Windows 2000 Compatible Access` group (SID `S-1-5-32-554`).
The catalog wording says the group "has broad membership", but the rule
operates per-member rather than over the breadth of the membership set
(see §12.1 / `[IMP-CAT-WORDING]`). Severity is fixed at `Medium`.

### 3.1 Effective SQL (copied from code)

```sql
SELECT o.object_guid, o.distinguished_name, o.sid, g.group_sid
FROM fact_group_membership_direct g
INNER JOIN dim_object o ON g.member_sid = o.sid
WHERE g.group_sid = 'S-1-5-32-554'
  AND o.is_deleted = 0
ORDER BY o.sid, o.object_guid
```

### 3.2 Post-SQL filters (in C#)

- _None._ Every row returned by the SQL is emitted as a finding; no in-code
  exclusions, no severity tiering, no krbtgt / broad-principal / privileged
  filter.

## 4. Data dependencies

| Table | Columns read | Required coverage module |
| --- | --- | --- |
| `dim_object` | `object_guid`, `distinguished_name`, `sid`, `is_deleted` | `Objects` |
| `fact_group_membership_direct` | `group_sid`, `member_sid` | `GroupMembership` |

`RuleCoverageRequirements["SEC-061"]` is `[Objects, GroupMembership]` —
matches the join + filter columns above. No transitive closure is consulted
(`fact_group_membership_closure` is **not** read), so the rule fires only
on **direct** membership in `S-1-5-32-554`.

## 5. Exclusions (and the reason each is correct)

| Exclusion | Mechanism | Justification |
| --- | --- | --- |
| Memberships in any other group | SQL `g.group_sid = 'S-1-5-32-554'` | This rule is specifically about the legacy backward-compatibility group; other broad groups are SEC-062 territory. |
| Members marked deleted (`is_deleted = 1`) | SQL `o.is_deleted = 0` (added in this audit) | A tombstoned principal cannot be authenticated against and is not a viable misconfiguration; emitting it is noise. |
| Members with no `dim_object` row | `INNER JOIN dim_object` on `member_sid = sid` | Without a captured object the finding has no remediable identity. Treated as a capture coverage gap (`Objects` module). |

Not excluded (intentionally subject to review):

- Broad SIDs (`Everyone`, `Authenticated Users`, `Anonymous`) — these are
  the **canonical** dangerous members of Pre-Win2k and the entire reason
  the rule exists. Excluding them would defeat the rule.
- Privileged-by-membership members — a member that is also transitively
  in Domain Admins is still a SEC-061 hit; the rule deliberately reports
  membership shape, not the member's tier.
- Disabled accounts — disabled-but-existing membership still represents a
  policy violation against the group; `is_deleted` is the only viability
  gate.
- Direct vs. closure membership — by design only `fact_group_membership_direct`
  is consulted, so a nested group whose closure includes Pre-Win2k does
  not propagate. This matches the per-row "remove this member" remediation
  guidance.

## 9. Output assertions (`Detail` and `ContextJson`)

The finding produced must include:

- `RuleId == "SEC-061"`
- `Severity == Medium`
- `SubjectSid` = the member's SID (never empty for emitted findings — see E11)
- `TargetKind == "object_guid"`
- `TargetId` = the member's GUID in `D` format
- `SourceEdgeId` = `null` (delegation-style finding)
- `FindingKey == "SEC-061|{member_sid}|{member_guid}"`
- `Detail` contains: `"is member of Pre-Windows 2000 Compatible Access"` and the member's DN (or GUID fallback)
- `ContextJson` non-null and contains:
  - `"evidence_type": "group_membership"`
  - `"condition": "PreWindows2000CompatibleAccess"`
  - `"member_dn"`: DN string or null
  - `"member_sid"`: member SID
  - `"group_sid": "S-1-5-32-554"`
  - `"object_guid"`: member GUID in `D` format
  - **No `"rule_id"` key** — `CreateDelegationFinding` does not inject it (cross-cutting `[IMP-CTX-RULEID]`).

## 12. Defects / deferred items

> Tag each entry with an `[IMP-xxx]` code (see `docs/rules/IMPROVEMENTS.md`). Resolved items are kept for historical context and are intentionally untagged.

1. **Catalog wording vs. behaviour** `[IMP-CAT-WORDING]` — catalog says
   the group "has broad membership" but the rule fires one finding per
   member regardless of breadth (a single member triggers a finding).
   `Accepted-with-known-limitation`: a per-member emission shape is the
   correct remediation unit, but the catalog description should be
   tightened (e.g., "_A principal is a direct member of the
   Pre-Windows 2000 Compatible Access group._").

2. **Tombstoned members surfaced** — fixed in this audit; SQL now includes
   `AND o.is_deleted = 0`. Pin test `WhenPreWindows2000MemberIsTombstoned_ThenSEC061DoesNotFire`
   protects the new behaviour. Resolved — no tag.

## 13. Improvement suggestions (not blocking)

> Tag each entry with an `[IMP-xxx]` code (see `docs/rules/IMPROVEMENTS.md`). If a needed tag does not exist, add it to the taxonomy first, then use it here.

1. `[IMP-DN-ENRICH]` — `Detail` and `ContextJson` carry SID + DN but no
   `sam_account_name` / display name. For a UI reviewer triaging a long
   member list, the friendly name is the cheapest disambiguator.

2. `[IMP-CTX-RULEID]` — `CreateDelegationFinding` does not inject a
   top-level `"rule_id"` field into `ContextJson`. Cross-cutting; tracked
   against every delegation-style rule.

3. `[IMP-PARITY-TEST]` — `RuleCatalogParityTests` does not assert per-rule
   that SEC-061's emitted severity matches the catalog default (`Medium`),
   that the category is `ConfigurationHygiene`, or that `mitre` is unset.
   Generic across most rules.

4. `[IMP-DEL-OBJ]` — broader sweep of `is_deleted` filtering across all
   evaluators is still open even though SEC-061 is now compliant.

5. Tombstone of `S-1-5-32-554` itself — the SQL filters on the **member**'s
   `is_deleted`, not the group's. If the BUILTIN container's `Pre-Windows
   2000 Compatible Access` group is somehow marked deleted (it cannot be
   in practice, but a tampered DB could), members still surface. Out of
   scope for the per-rule fix; treat as part of an `[IMP-DEL-OBJ]` sweep.

6. **`mitre` attribute absent** — most ConfigurationHygiene rules in the
   catalog also lack a MITRE id, so this is not a SEC-061-specific issue.
   Consider an ATT&CK mapping pass after the rule audit completes (could
   become `[IMP-MITRE]` if it gains scope).
