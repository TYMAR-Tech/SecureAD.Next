## 1. Catalog claim (verbatim from `rules.yaml`)

```yaml
- id: SEC-201
  name: "DACL/Owner Control on Domain Root"
  description: >-
    A principal has WriteDACL, WriteOwner, or ownership control on the domain root object, enabling full domain takeover by modifying the domain DACL or taking ownership.
  severity: Critical
  category: DangerousPermissions
  remediation: >-
    Remove unnecessary WriteDACL, WriteOwner, or ownership control from the domain root.
  mitre: T1222.001
  tags: ["tier-zero", "domain-control", "permission-modification"]
```

Source: `src/SecureAD.Core/Findings/Rules/rules.yaml` lines 566–575.

## 2. Intended detection (plain English)

Fire one Critical finding per `(non-privileged source, domain-root target)` pair when a `fact_control_edge` exists with `control_type ∈ { WriteDacl, WriteOwner, Owns }` against an object whose `object_class = 'domainDNS'`. Any one of those rights on the domain root is a full-domain takeover primitive (`WriteDacl` rewrites the domain DACL, `WriteOwner` lets the principal take ownership and then rewrite the DACL, `Owns` already grants both implicitly). Deny-cancelled edges (`deny_cancelled = 1`) must not fire — `ControlEdgeService` already encodes deny semantics there. Tombstoned domain objects (`is_deleted = 1`) must not fire because a deleted root cannot host a live grant. Privileged sources (well-known admin SIDs/RIDs **or** transitively privileged-by-membership) must not fire — the rule targets unexpected principals.

### 3.1 Effective SQL (copied from code)

```sql
SELECT e.source_sid, e.target_object_guid, o.distinguished_name, e.edge_id, e.control_type
FROM fact_control_edge e
INNER JOIN dim_object o ON e.target_object_guid = o.object_guid
WHERE e.deny_cancelled = 0
  AND e.control_type IN ('WriteDacl', 'WriteOwner', 'Owns')
  AND o.object_class = 'domainDNS'
  AND o.is_deleted = 0
ORDER BY e.source_sid, e.target_object_guid, e.control_type
```

### 3.2 Post-SQL filters (in C#)

- `IsPrivilegedPrincipal(sid, context.PrivilegedSids)` — drops well-known admins and transitively privileged subjects. `IsPrivilegedPrincipal` already delegates to `IsAdminSid` for well-known RIDs/system SIDs, so a single call covers both. (Previously `IsAdminSid(sid) || IsPrivilegedPrincipal(...)` — the redundant disjunction was collapsed under `[IMP-PRIV-MEMB-SRC]`.)

## 5. Exclusions (and the reason each is correct)

| Exclusion | Mechanism | Justification |
| --- | --- | --- |
| Edges with non-takeover rights | SQL `e.control_type IN ('WriteDacl', 'WriteOwner', 'Owns')` | The catalog scopes the rule to the three rights that grant full DACL control; other Tier-0 rights are covered by SEC-204. |
| Non-domain-root targets | SQL `o.object_class = 'domainDNS'` | The rule's whole premise is the domain head; OUs, AdminSDHolder, and DC OU are covered by SEC-006 / SEC-120 / SEC-121 / SEC-204. |
| Deny-cancelled edges | SQL `e.deny_cancelled = 0` | A deny ACE that cancels the upstream allow already neutralises the grant; firing would be noise. |
| Tombstoned domain objects | SQL `o.is_deleted = 0` | A deleted domain object cannot host an actionable grant. |
| Well-known admin sources | C# `IsAdminSid(sid)` | DA / EA / SA / Builtin Administrators legitimately hold these rights. |
| Transitively privileged sources | C# `IsPrivilegedPrincipal(sid, context.PrivilegedSids)` | DA / EA members inherit the same trust; surfacing them is noise. |

Not excluded (intentionally subject to review):

- Broad SIDs (`Everyone`, `Authenticated Users`, `Anonymous Logon`, `Domain Users`). Not excluded — broad SIDs with WriteDACL on the domain root **must** fire (SEC-060 also fires at Critical, but SEC-201 is the rule catalog wires for the specific "domain root takeover" claim). `IsPrivilegedPrincipal` returns false for broad SIDs.
- Cross-domain trustees. In scope.

## 13. Improvement suggestions (not blocking)

1. `[IMP-DEL-OBJ]` — Resolved on SEC-201. After SEC-204 is verified, the cross-cutting sweep should narrow to `KerberosRuleEvaluator` (SEC-020 / 021 / 022 / 023) — those have explicit `*_KnownLimitation` tests today.
2. `[IMP-COV-MEMB]` — `RuleCoverageRequirements["SEC-201"]` does not declare `GroupMembership` even though `IsPrivilegedPrincipal` consumes the closure. Same gap as SEC-025 / SEC-080 / SEC-081 / SEC-090 / SEC-123 / SEC-124 / SEC-126 / SEC-131.
3. `[IMP-PRIV-MEMB-SRC]` — Mechanical redundancy resolved: the post-SQL filter now uses a single `IsPrivilegedPrincipal(sid, context.PrivilegedSids)` call (the historical `IsAdminSid(sid) || IsPrivilegedPrincipal(...)` disjunction was collapsed), bringing SEC-201 in line with SEC-120 / 121 / 123 / 124. The semantic question — whether transitively privileged sources should be excluded outright vs. severity-tiered — is still open at the cross-cutting level (see `IMPROVEMENTS.md`).
4. `[IMP-DN-ENRICH]` — `Detail` interpolates `dn ?? targetGuid.ToString()`; the trustee SID is surfaced raw with no `sam_account_name` join. Parity with SEC-100 / 101 / 102 / 120 / 121 / 122 / 123 / 124 / 126 / 131.
5. `[IMP-PARITY-TEST]` — No per-rule parity assertion that the catalog row (`name`, `severity`, `category`, `mitre`, `tags`) wired into `BuiltInRules` matches `rules.yaml` for SEC-201. Cross-cutting.
6. `[IMP-DUP-RULE]` — Broad SID with `WriteDacl` on the domain root surfaces under both SEC-201 (Critical) and SEC-060 (Critical). Both findings are technically correct, but operators see the same primitive twice. Decision: either the rules deduplicate (SEC-060 is the broad-SID specialist), or the catalog explicitly states they are intentionally redundant. Same gap pattern as SEC-010 / 011 / 013 / 020 / 021 / 022 / 023 / 076 / 077.
7. `[IMP-CTRL-SCOPE]` — **RESOLVED by documented partition.** SEC-201's spill list is `IN ('WriteDacl', 'WriteOwner', 'Owns')` (verified `AdvancedRuleEvaluator.EvaluateWriteDaclOwnerOnDomainRoot`). `GenericAll` is **intentionally not** widened in here — it is routed to SEC-204 (spill-to-Tier-0) and SEC-060 (broad-SID), so a single primitive is not triple-counted across the takeover family. This is the deliberate counterpart to the SEC-006 / SEC-024 / SEC-025 / SEC-081 widening: those rules widen because no sibling covers the broad-grant path; SEC-201 does not, because SEC-204 / SEC-060 already do. No code change.
8. `[IMP-TGT-CLASS]` — The class filter assumes `domainDNS` is the only domain-root class. In multi-domain or partitioned configurations, `crossRefContainer` / NC heads (`configuration`, `schema`) carry the same takeover semantics; SEC-201 silently misses them today. Cross-cutting tag — see also SEC-006 / 014 / 024–026.
