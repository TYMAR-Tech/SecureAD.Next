### 3.3 Notes on the SQL

- `INNER JOIN dim_object o ON g.group_sid = o.sid` â€” a group present in `fact_group_membership_direct` but absent from `dim_object` is silently dropped. See Â§8 E5 and `[IMP-OBJ-JOIN]` in Â§13.
- `COUNT(*)` counts rows in `fact_group_membership_direct` (direct members only). Transitive (closure) membership is not consulted. The description explicitly says "direct"; the SQL is consistent.
- `HAVING COUNT(*) > $threshold` â€” strict `>`, so a group with exactly threshold members does NOT fire.
- `g.member_sid` is not validated (e.g., the member could be a tombstoned object). The rule treats every row in `fact_group_membership_direct` as a valid member, which is the intent for a "size" check.
- The SQL does not filter `o.is_deleted`. A tombstoned but oversized group would still fire. See `[IMP-DEL-OBJ]` in Â§13.
- The group's display name (`Domain Admins`, etc.) in `Detail` and `ContextJson.group_name` is **hardcoded** from the threshold tuple. The actual `sAMAccountName` from `dim_object` is not read. A renamed group still fires correctly (by SID/RID) but the Detail says "Domain Admins". See `[IMP-NAME-DERIVE]` in Â§13.

## 5. Exclusions (and the reason each is correct)

| Exclusion | Mechanism | Justification |
| --- | --- | --- |
| Direct member count `<= threshold` | SQL `HAVING COUNT(*) > $threshold` | Below or equal to threshold is, by catalog definition, acceptable. |
| Group is not one of the four privileged groups | SQL `WHERE g.group_sid LIKE '%-512' / '%-518' / '%-519'` or `= 'S-1-5-32-544'` | The rule scope is exactly the four highest-tier groups. Account Operators / Server Operators / etc. are not in scope. |
| Group missing from `dim_object` | SQL `INNER JOIN dim_object o ON g.group_sid = o.sid` | Without object metadata (GUID, DN), the finding cannot be constructed. See `[IMP-OBJ-JOIN]` in Â§13. |
| Closure / transitive membership | SQL reads `fact_group_membership_direct` only | The catalog says "direct"; transitive membership is SEC-051's territory (Nested Group in DA). |

Not excluded (intentionally subject to review):

- **Tombstoned groups (`o.is_deleted = 1`)**. `[IMP-DEL-OBJ]` in Â§13.
- **Group name mismatch**. The `Detail`/`group_name` is hardcoded; if the actual group has been renamed (e.g., `AltDomainAdmins` with RID `-512`), the finding still says "Domain Admins". `[IMP-NAME-DERIVE]` in Â§13.
- **Cross-domain duplicates**. Each domain has its own `-512` / `-518` / `-519`. The `%-RID` pattern catches them all, producing one finding per domain.
- **Empty groups**. A group with zero members cannot satisfy `COUNT(*) > 0`, so no row appears in `fact_group_membership_direct` for it â€” implicitly excluded.
