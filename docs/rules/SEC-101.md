## 1. Catalog claim (verbatim from `rules.yaml`)

```yaml
- id: SEC-101
  name: "Service Account with Non-Expiring Password"
  description: >-
    A service account has the DONT_EXPIRE_PASSWORD flag set and is not a Group Managed Service Account.
  severity: Medium
  category: AccountSecurity
  remediation: >-
    Migrate to Group Managed Service Accounts (gMSA) or enforce regular password rotation.
  mitre: T1078.002
  tags: ["service-account", "password-policy"]
```

Source: `src/SecureAD.Core/Findings/Rules/rules.yaml` lines 467–476.

## 2. Intended detection (plain English)

For every non-deleted service account (`msDS-ManagedServiceAccount` class, or any object under `OU=Service Accounts` / `CN=Service Accounts`) that has a `dim_delegation` row with `delegation_type = 'DontExpirePassword'` (derived from the `UserAccountControl` bit `0x10000` `DONT_EXPIRE_PASSWORD` by `DirectObjectWriter.ExtractDelegations`), emit one finding per account. Group Managed Service Accounts (`msDS-GroupManagedServiceAccount`) are deliberately excluded because gMSAs rotate passwords automatically via the Key Distribution Service and the `DONT_EXPIRE_PASSWORD` bit is benign for them. Severity is `Medium` because the issue is a hygiene / least-credential-lifetime concern, not a direct authentication-bypass primitive.

## 4. Effective SQL executed (after defect fix)

```sql
SELECT o.object_guid, o.distinguished_name, o.sid
FROM dim_delegation d
INNER JOIN dim_object o ON d.object_guid = o.object_guid
WHERE d.delegation_type = 'DontExpirePassword'
  AND o.is_deleted = 0
  AND o.object_class != 'msDS-GroupManagedServiceAccount'
  AND (o.object_class = 'msDS-ManagedServiceAccount'
    OR o.distinguished_name LIKE '%OU=Service Accounts%'
    OR o.distinguished_name LIKE '%CN=Service Accounts%')
ORDER BY o.sid, o.object_guid
```

## 10. Severity rationale

`Medium` matches `rules.yaml` and is loaded via `BuiltInRules.ById["SEC-101"].DefaultSeverity`. A non-expiring service-account password is a least-credential-lifetime hygiene issue: it amplifies the blast radius of any credential exposure, but does not itself enable authentication bypass. `Medium` is appropriate — `High` is reserved for active privilege scenarios (e.g., SEC-100 — SA in a privileged group), and `Low` would understate the long-tail exposure that "this password has not rotated in years" implies.

## 11. MITRE mapping

`T1078.002` — _Valid Accounts: Domain Accounts_. Reasonable fit for the credential-persistence angle. Same `[IMP-MITRE-FIT]` caveat as the rest of the `AccountSecurity` family.
