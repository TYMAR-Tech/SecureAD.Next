## 1. Catalog claim (verbatim from `rules.yaml`)

```yaml
- id: SEC-065
  name: "Privileged Local Group Membership via Restricted Groups"
  description: >-
    A Group Policy Restricted Groups assignment (the [Group Membership] section of a GPO security
    template) configures the membership of a privileged builtin local group — Administrators, Backup
    Operators, Server Operators, Account Operators, Print Operators, or Power Users — on every computer
    the GPO targets. ... a grant to a broad principal is a direct escalation path.
  severity: High
  category: ConfigurationHygiene
  remediation: >-
    Confirm the local group membership is an intended operational role. If not, remove the principal ...
  mitre: T1484.001
  tags: ["gpo", "restricted-groups", "local-admin", "review", "sysvol"]
```

## 2. Intended detection (plain English)

A GPO's Restricted Groups policy (`GptTmpl.inf [Group Membership]`, captured into `dim_gpo_setting`)
configures the membership of a **privileged builtin local group** on every computer the GPO targets.
Because the membership lands in a machine-local group rather than a directory group, it is invisible
to the directory group-membership rules (SEC-050/051/052/060), which only ever see domain groups —
yet it can confer local administrator, and on a domain controller domain-level, control fleet-wide.

Each grant is a **review** finding (`disposition = review_required`). Severity is tiered by the
**controlled group** (`LocalPrivilegedGroupCatalog`), then escalated by the **member**:
- **Critical** when the member is a **broad principal** (Everyone / Authenticated Users / Domain
  Users) — every user gains the local privilege fleet-wide, regardless of the group's base tier.
- Otherwise the group's base tier: **Critical** Administrators (544); **High** Backup/Server/Account/
  Print Operators (551/549/548/550); **Medium** Power Users (547).

### 3.1 Effective SQL

```sql
SELECT s.gpo_guid, s.setting_key, s.setting_value, gpo.distinguished_name
FROM dim_gpo_setting s
INNER JOIN dim_object gpo ON s.gpo_guid = gpo.object_guid
WHERE s.source_file = 'GptTmpl.inf' AND s.section = 'Group Membership'
  AND s.setting_value IS NOT NULL AND TRIM(s.setting_value) != ''
ORDER BY s.gpo_guid, s.setting_key
```

### 3.2 Capture shape + per-member logic (in C#)

The `[Group Membership]` section has two mirror-image key shapes (confirmed against the lab DB):
- `*<GroupSID>__Members = *<MemberSID>,...` — authoritative membership of the controlled group.
- `*<PrincipalSID>__Memberof = *<GroupSID>,...` — the principal is made a member of each listed group.

`ParseGroupMembershipKey` strips the `*` and the `__Members`/`__Memberof` suffix; the evaluator
reduces **both** forms to `(controlledGroupSid, memberSid)` pairs. For each pair:
1. Skip unless `LocalPrivilegedGroupCatalog.Find(controlledGroupSid)` is non-null (in scope).
2. Skip if `ShouldExcludePrivilegedTrustee(memberSid, context.PrivilegedSids)` — well-known admin RIDs
   **and** members transitively privileged via group closure (e.g. a named account that is a member of
   Domain Admins). Such a member is already Tier-0, so pinning it into a local group confers nothing
   new — the standard hardening pattern. Closure-aware, matching SEC-063.
3. Otherwise emit: `Critical` if `BroadPrincipalCatalog.IsBroad(memberSid)`, else `group.Tier`.
   FindingKey discriminator = `controlledGroupSid|memberSid` (one finding per group per member).

## 4. The privileged local-group catalog (grounded in Microsoft docs)

| Builtin local group | SID | Base tier | Capability |
| --- | --- | --- | --- |
| Administrators | S-1-5-32-544 | `Critical` | Full control of the machine; on a DC, of the domain. |
| Backup Operators | S-1-5-32-551 | `High` | SeBackup/SeRestore — read/replace any file; NTDS.dit theft on a DC. |
| Server Operators | S-1-5-32-549 | `High` | Manage DC services/shares; log on locally to DCs. |
| Account Operators | S-1-5-32-548 | `High` | Create/modify accounts; log on to DCs. |
| Print Operators | S-1-5-32-550 | `High` | SeLoadDriver — load kernel-mode drivers. |
| Power Users | S-1-5-32-547 | `Medium` | Legacy elevated-user group; low privilege on modern Windows. |

Source: Microsoft "Active Directory security groups" (well-known SID + default user rights per builtin
group) and "Description of group policy restricted groups" (KB 279301). Pure access groups (Remote
Desktop Users 555, Distributed COM Users 562, Remote Management Users 580) are **out of v1 scope** —
they grant a logon/connection surface rather than local privilege (see §11).

## 5. Exclusions (and why each is correct)

| Exclusion | Mechanism | Justification |
| --- | --- | --- |
| Non-privileged local groups | `LocalPrivilegedGroupCatalog.Find` returns null | Only groups conferring a privileged capability are in scope. `BUILTIN\Users` (545), Guests (546), and the access-only groups (555/562/580) are not flagged. |
| Already-privileged members | `ShouldExcludePrivilegedTrustee` | **Pinning a principal that is already privileged — a well-known admin RID (Domain Admins) or a named account transitively privileged via group closure (`context.PrivilegedSids`) — into a local privileged group is the recommended hardening pattern** and grants no new escalation. Flagging it would be a false positive. Closure-aware, matching SEC-063. |
| Empty `__Members` line | SQL `TRIM(setting_value) != ''` + parser yields no SID | An enforce-"no members" entry carries no member to flag. |
| Unrecognized key shape | `ParseGroupMembershipKey` returns `(null, _)` | Only `__Members`/`__Memberof` lines are membership grants. |
| Non-Group-Membership rows | SQL `section = 'Group Membership'` | Registry.pol / Privilege Rights / other sections out of scope. |

## 8. Output assertions

`ContextJson` carries `gpo_dn`, `controlled_group_sid`, `controlled_group_name`, `member_sid`,
`is_broad_principal`, `restricted_groups_relation` (`members` | `memberof`),
`disposition = "review_required"`, `vector = "restricted_groups"`. `Detail` leads "Review local group
membership:". Severity `Critical` iff broad member, else the group tier. FindingKey is
`SEC-065|<member>|<gpoGuid>|<controlledGroupSid>|<memberSid>`.

## 9. Disposition model

Same two-axis model as SEC-063/064: severity = impact (the controlled group's privilege, with a
broad member forcing Critical), `disposition = review_required` = certainty (a Restricted Groups
membership is sometimes a supported operational role, e.g. a server-support team into local admins on
a server OU, so confirm intent; if not what the org meant, it is the fix).

## 10. Live lab validation

Root + 2-child lab (`ba.ad.lab` child): the only Restricted Groups entry pins
`CN=ba.admin,OU=Users,OU=BA Lab` (RID 1104) into `BUILTIN\Power Users` (547) via GPO
`{534EF724-FA3E-4782-B439-308785677F52}`. The persisted `fact_finding` enrichment
(`subject_privileged_via`) shows `ba.admin` is a transitive member of Domain Admins (512), Schema
Admins (518), Enterprise Admins (519), and `BUILTIN\Administrators` (544) — i.e. **already Tier-0**.
With the closure-aware exclusion (`ShouldExcludePrivilegedTrustee`), pinning an already-privileged
account into a local group confers no new escalation, so SEC-065 correctly returns **0** here (true
negative — the same hardening-pattern logic as N1/N4). Probe: `LabDbProbe.ValidateSec065_AgainstLab`
(read-only, lab-only) confirms the `*<GroupSID>__Members` capture shape, the member-SID resolution,
and the closure-aware exclusion end-to-end.

The positive path (a **non-privileged** member into a local privileged group, which is the actual
escalation SEC-065 exists to catch) is pinned by synthetic tests (§6); adding a plain non-admin lab
account to Power Users or local Administrators will exercise it end-to-end in a future capture.

## 11. Defects / deferred items

1. **Access-only local groups** — Remote Desktop Users (555), Distributed COM Users (562), Remote
   Management Users (580) are out of v1 scope. They grant a logon/connection surface rather than local
   privilege and are a separate, noisier detection. Deferred.
2. **GPO scope / blast radius** — the finding names the GPO but not which computers/OUs it is linked
   to (Administrators via a DC-linked GPO is the worst case). Correlating with gPLink targets would
   let an operator gauge blast radius. Deferred enhancement (shared with SEC-064 §11.4).
3. **Friendly-name members** — a value with a non-`*` friendly name (rare; capture stores `*SID`) is
   surfaced raw for manual review rather than resolved. Acceptable (errs toward visibility).
4. `[IMP-DN-ENRICH]` — `member_sid` is surfaced raw; a `dim_principal` join for `member_name` would
   improve readability. Family-wide.
