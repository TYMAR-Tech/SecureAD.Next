## 2. Intended detection (plain English)

> Written from §1 only. Compared against §3 below.

Fire when an Active Directory object that is privileged (determined by well-known admin RIDs or transitive membership in privileged groups) is **owned** by a principal that is not one of the expected administrative identities. The catalog description is minimal; the code must define "privileged object" and "non-expected owner."

### 3.1 Effective SQL (copied from code)

```sql
SELECT o.object_guid, o.distinguished_name, o.sid, o.owner_sid
FROM dim_object o
WHERE o.owner_sid IS NOT NULL
  AND o.sid IS NOT NULL
ORDER BY o.sid, o.object_guid
```

Notes:

- The SQL reads every `dim_object` row where both `sid` and `owner_sid` are non-NULL. No table-level filtering on privileged groups or admin RIDs — all privilege classification happens post-SQL in C#.
- `owner_sid` is populated by `DirectAceWriter` during the security descriptor capture pass (`SecurityDescriptors` module). Without SD coverage, `owner_sid` is NULL for all rows → zero findings.
- `ORDER BY o.sid, o.object_guid` provides deterministic ordering but has no semantic filtering effect.

### 3.2 Post-SQL filters (in C#)

For every row returned by the SQL:

1. **Subject privilege check** (line 128):  
   `if (sid is null || !RuleEvaluatorHelpers.IsPrivilegedPrincipal(sid, context.PrivilegedSids)) continue;`  
   - `IsPrivilegedPrincipal` returns `true` when the SID is a well-known admin RID (via `IsAdminSid`) **or** when the SID appears in `context.PrivilegedSids` (built from `fact_group_membership_closure` by `FindingsService.BuildPrivilegedSidSet`).
   - Unprivileged objects are silently skipped — no finding.

2. **Owner exclusion check** (line 131):  
   `if (RuleEvaluatorHelpers.IsAdminSid(ownerSid) || RuleEvaluatorHelpers.PrivilegedSystemSids.Contains(ownerSid)) continue;`  
   - If the owner is a well-known admin RID **or** a privileged system SID (SYSTEM, Enterprise DCs, Creator Owner, Self, BUILTIN admin groups), skip the finding.
   - Note: the `|| PrivilegedSystemSids.Contains(ownerSid)` is redundant because `IsAdminSid` already returns `true` for any SID in `PrivilegedSystemSids` (line 83). Benign; captured as a minor cleanup opportunity in §13.

3. **Always emit** the finding if the object passed both filters.

## 5. Exclusions (and the reason each is correct)

| Exclusion | Mechanism | Justification |
| --- | --- | --- |
| `o.owner_sid IS NULL` | SQL `o.owner_sid IS NOT NULL` | An object without a captured owner cannot have a misconfigured owner. Rows with NULL `owner_sid` are excluded by design. |
| `o.sid IS NULL` | SQL `o.sid IS NOT NULL` | An object without a SID cannot be classified as privileged. Excluded. |
| Unprivileged objects (subjects) | Post-SQL `!IsPrivilegedPrincipal(sid, context.PrivilegedSids)` | Only privileged objects are in scope. Non-privileged objects are not reviewed for ownership. |
| Well-known admin RID owners | Post-SQL `IsAdminSid(ownerSid)` | RID 500 (Administrator), RID 502 (krbtgt), RID 512 (Domain Admins), RID 516 (Domain Controllers), RID 518 (Schema Admins), RID 519 (Enterprise Admins), RID 520 (GPCO), RID 521 (RoDC), RID 526 (Key Admins), RID 527 (Enterprise Key Admins). Expected admin owners. |
| Privileged system SID owners | Post-SQL `PrivilegedSystemSids.Contains(ownerSid)` | `S-1-5-18` (Local System), `S-1-5-9` (Enterprise DCs), `S-1-3-0` (Creator Owner), `S-1-5-10` (Self), and BUILTIN admin operator groups (`S-1-5-32-544`, `S-1-5-32-548..552`). These are expected administrative owners for tier-0 objects. |

Not excluded (intentionally subject to review):

- **krbtgt account (RID 502) as a subject**. Unlike SEC-032 (which explicitly excludes krbtgt via `IsKrbtgtSid`), SEC-031 does **not** exclude krbtgt. A krbtgt account owned by a non-admin principal is genuinely a tier-0 ownership misconfiguration and should fire. Pinned by test `WhenKrbtgtOwnedByNonAdmin_ThenSEC031Fires`.
- **Privileged-by-membership owners**. The owner exclusion is RID-based via `IsAdminSid` and does **not** consult `context.PrivilegedSids`. An owner who is privileged only by transitive group membership (e.g., a regular user SID that is a closure member of Domain Admins) will still fire a finding. Captured under `[IMP-PRIV-MEMB-SRC]` in §12.
- **Deleted objects (`is_deleted = 1`)**. The SQL does not filter tombstones. A privileged tombstone with a non-admin owner will fire. `[IMP-DEL-OBJ]` in §13.

## 9. Output assertions (`Detail` and `ContextJson`)

For a privileged object (e.g., Domain Admins group) owned by a non-admin user, the finding must include:

- `RuleId == "SEC-031"`
- `Severity == High`
- `TargetKind == "object_guid"`
- `TargetId == objectGuid` (D-formatted)
- `SubjectSid == sid` (the privileged object's SID)
- `SourceEdgeId is null` (delegation finding)
- `SourcePathId is null`
- `FindingKey == "SEC-031|{subjectSid}|{objectGuid}"`
- `Detail` contains: `"Privileged object"`, the object DN or GUID, `"owned by non-admin"`, and the `ownerSid`.
- `ContextJson` keys:
  - `evidence_type` = `"account_hygiene"`
  - `condition` = `"NonDefaultOwnerOnPrivilegedObject"`
  - `object_dn` = the DN (string, may be `null` if DN is `null` in `dim_object`)
  - `object_sid` = the subject SID (string)
  - `owner_sid` = the owner SID (string)
  - `owner_is_admin` = `false`
  - `object_guid` = the GUID (D-formatted string)

`ContextJson` does **not** carry a top-level `"rule_id"` field — same `[IMP-CTX-RULEID]` shape as SEC-026, SEC-030. Captured in §12.

## 12. Defects / deferred items

1. **Coverage map incomplete** — **Resolved in this session.**  
   `RuleCoverageRequirements["SEC-031"] = [Objects]` was missing `SecurityDescriptors` (required because `owner_sid` is populated by `DirectAceWriter` during SD capture) and `GroupMembership` (required because `context.PrivilegedSids` is built from `fact_group_membership_closure`).  
   **Fix:** changed to `[Objects, SecurityDescriptors, GroupMembership]` in `src/SecureAD.Infrastructure/Findings/FindingsService.cs` line 49.

2. `[IMP-PRIV-MEMB-SRC]` — **Accepted-with-known-limitation.**  
   The owner exclusion check (`IsAdminSid(ownerSid) || PrivilegedSystemSids.Contains(ownerSid)`) is RID-based and does **not** consult `context.PrivilegedSids`. An owner who is privileged only via transitive group membership (e.g., a regular user SID that is a closure member of Domain Admins) is still flagged as "non-admin" and fires a finding. Pinned by test `WhenPrivilegedObjectOwnedByPrivilegedByMembership_ThenSEC031FiresAndIsAcceptedLimitation`. Deferred to the cross-cutting `[IMP-PRIV-MEMB-SRC]` workstream.

3. `[IMP-CTX-RULEID]` — **Accepted-with-known-limitation.**  
   `ContextJson` produced by `CreateDelegationFinding` does not embed a top-level `"rule_id"` field. Same shape issue as documented in SEC-026 and SEC-030 cards.

4. `[IMP-DEL-OBJ]` — **Accepted-with-known-limitation.**  
   SQL does not filter `is_deleted = 1`. A privileged tombstoned object with a non-admin owner still fires. Deferred to the cross-cutting `[IMP-DEL-OBJ]` workstream.

5. `[IMP-DN-ENRICH]` — **Accepted-with-known-limitation.**  
   `Detail` and `ContextJson` carry DNs and SIDs but no `sAMAccountName` / `display_name`. Operators identifying which principal to remediate typically search by `sAMAccountName`. Deferred to the cross-cutting `[IMP-DN-ENRICH]` workstream.

6. `[IMP-PARITY-TEST]` — **Accepted-with-known-limitation.**  
   No per-rule severity / category / tag parity assertion exists for SEC-031 in `RuleCatalogParityTests`. Deferred to the cross-cutting `[IMP-PARITY-TEST]` workstream.
