## 1. Catalog claim (verbatim from `rules.yaml`)

```yaml
- id: SEC-081
  name: "Unexpected Principal can Create GPO Links"
  description: >-
    A principal can link GPOs to OUs via write access to the gPLink attribute.
  severity: High
  category: ConfigurationHygiene
  remediation: >-
    Restrict gPLink write access to authorized GPO administrators.
  mitre: T1484.001
  tags: ["gpo", "configuration"]
```

Source: `src/SecureAD.Core/Findings/Rules/rules.yaml` lines 412–421.

## 2. Intended detection (plain English)

Surface any principal (other than expected GPO administrators) that holds the `LinkGPO` capability — i.e. write access to the `gPLink` attribute on a container that can host GPO links (OU, site, or domain root). A principal with `gPLink` write can attach an existing GPO to that scope; combined with SEC-080 (modify-GPO) it is a documented Tier 0 escalation path (MITRE T1484.001 — _Domain or Tenant Policy Modification_). Severity is `High` rather than `Critical` because the principal also needs a writable or attacker-controlled GPO to fully exploit the link.

### 3.1 Effective SQL (copied from code)

```sql
SELECT e.source_sid, e.target_object_guid, MIN(o.distinguished_name) AS dn,
       MIN(e.edge_id) AS edge_id, MIN(e.control_type) AS control_type,
       MAX(CASE WHEN e.control_type = 'LinkGPO' THEN 1 ELSE 0 END) AS has_specific
FROM fact_control_edge e
INNER JOIN dim_object o ON e.target_object_guid = o.object_guid
WHERE e.control_type IN ('LinkGPO', 'GenericAll', 'GenericWrite', 'WriteAllProperties')
  AND e.deny_cancelled = 0
  AND o.object_class IN ('organizationalUnit', 'domainDNS', 'site')
GROUP BY e.source_sid, e.target_object_guid
ORDER BY e.source_sid, e.target_object_guid
```

The widened control-type set comes from `PropertyWriteEquivalents(ControlType.LinkGPO)` = `LinkGPO` + the broad property writes. `has_specific` drives `link_capability` (`specific` when a targeted `LinkGPO` edge is present, else `via_broad_write`) so a Manage-Group-Policy-Links delegation is distinguishable from a broad OU write that merely subsumes gPLink. The container class filter makes the broad rights safe to include (gPLink only exists on OU / domain root / site).

### 3.2 Post-SQL filters (in C#)

- `if (excludeAdmins && IsAdminSid(sid)) continue;` — `excludeAdmins: true` is passed from `GpoRuleEvaluator`, so well-known admin SIDs (`Domain Admins` RID 512, `Enterprise Admins` RID 519, `SYSTEM` `S-1-5-18`, `Enterprise DCs` `S-1-5-9`, `BUILTIN\Administrators` `S-1-5-32-544`, etc.) are skipped. Broad principals (`Everyone`, `Authenticated Users`, `Anonymous`) intentionally pass through — see §5.

## 5. Exclusions (and the reason each is correct)

| Exclusion | Mechanism | Justification |
| --- | --- | --- |
| Non-property-write control types on the container | SQL `control_type IN ('LinkGPO', 'GenericAll', 'GenericWrite', 'WriteAllProperties')` constrained to `object_class IN ('organizationalUnit', 'domainDNS', 'site')` | `[IMP-CTRL-SCOPE]` resolved — SEC-081 now fires on a broad write to a GPO-linkable container (which confers `gPLink` write), not just the literal `LinkGPO` edge. DACL-pivot rights stay SEC-060's domain for broad sources. |
| Cancelled deny ACEs | SQL `e.deny_cancelled = 0` | Edges marked `deny_cancelled = 1` mean an effective-access pass found a deny ACE that neutralises the allow; the principal does not actually hold the right. |
| Well-known admin sources | C# `IsAdminSid(sid)` (via `excludeAdmins: true`) | Expected GPO administrators (Domain Admins, Enterprise Admins, SYSTEM, Enterprise DCs, BUILTIN\Administrators, Schema Admins, Group Policy Creator Owners RID 520, etc.) linking GPOs is normal operation, not a misconfiguration. |

Not excluded (intentionally subject to review):

- **Broad principals.** `Everyone` / `Authenticated Users` / `Anonymous` fall through `IsAdminSid` (`BroadSids` are not admins) and surface as SEC-081 findings. Intentional: broad-SID gPLink write is the canonical "anyone can link a GPO" misconfiguration; SEC-060 only covers the generic broad-write case at `High` without GPO-link-specific provenance. Pinned in §7 / §8.
- **Privileged-by-membership sources.** A user who transitively reaches Domain Admins (via nested group membership) is **not** excluded — the rule still fires, but `ContextJson.source_admin_classification = "PrivilegedByMembership"` flags the case for downstream tiering. Aligned with SEC-024 / SEC-025 / SEC-080; cross-cutting `[IMP-PRIV-MEMB-SRC]`.
- **Target object class.** The helper SQL does not constrain `object_class`. In practice the capture pipeline only emits `LinkGPO` for ACEs that actually reference the gPLink attribute GUID — and the AD schema only allows that attribute on `organizationalUnit`, `domainDNS`, and `site` containers — so the missing class predicate is not a defect today. If a future capture pipeline regression emits a stray `LinkGPO` edge against a wrong class, the rule will surface it. See §8 / E10.
- **Deleted targets (`is_deleted = 1`).** The SQL does not filter `dim_object.is_deleted`. Same family-wide gap as SEC-080 — cross-cutting `[IMP-DEL-OBJ]`.

- `RuleId == "SEC-081"`
- `Severity == High`

- `ContextJson` non-null and contains:
  - `"rule_id": "SEC-081"`
  - `"source_sid"`, `"target_guid"`, `"target_dn"`, `"control_type": "LinkGPO"`

  - `"source_is_privileged_by_membership"`, `"source_is_broad_principal"` booleans

## 12. Defects / deferred items

> Tag each entry with an `[IMP-xxx]` code (see `docs/rules/IMPROVEMENTS.md`).

1. `[IMP-COV-MEMB]` — `RuleCoverageRequirements["SEC-081"] = [Objects, SecurityDescriptors, ControlEdges]` omits `GroupMembership`, but `CreateEdgeFinding` is called with `privilegedSids: context.PrivilegedSids` (built from `fact_group_membership_closure`) and emits `source_admin_classification` / `source_is_privileged_by_membership` in `ContextJson`. If GroupMembership coverage is incomplete, a transitively-privileged source silently degrades to `"NonPrivileged"` and the stamper does not attach a `coverage_reason`. Same shape as SEC-025 / SEC-076 / SEC-077 / SEC-080. **Status:** `Accepted-with-known-limitation` — fixed once across all affected rules under the cross-cutting `[IMP-COV-MEMB]` sweep rather than per-rule.

## 13. Improvement suggestions (not blocking)

> Tag each entry with an `[IMP-xxx]` code (see `docs/rules/IMPROVEMENTS.md`).

1. `[IMP-CTRL-SCOPE]` — **RESOLVED + honestly labeled.** SEC-081 matches the property-write equivalence set `PropertyWriteEquivalents(LinkGPO)` = `{LinkGPO, GenericAll, GenericWrite, WriteAllProperties}` on container targets, because a non-object "write all properties" / `GenericAll` ACE genuinely includes `gPLink` write (verified against Microsoft adschema `a-gplink` + the "ACEs to Control Access" property-inheritance semantics — gPLink is a normal, non-confidential, non-system-only attribute). **Lab finding:** of 1040 real findings, only **1** was a targeted `LinkGPO` edge; **1039** were broad `WriteAllProperties` on OUs (each a true positive — those principals can link a GPO — but a much broader delegation than "Manage Group Policy Links"). To stop the 1 targeted delegation being indistinguishable from the 1039, the dedicated `EvaluateGpoLink` method adds a `link_capability` context field (`specific` vs `via_broad_write`); count is unchanged (no coverage loss). Pinned by `WhenPrincipalHasWriteAllPropertiesOnOu_ThenSEC081FiresViaBroadWrite`, `WhenPrincipalHasGenericWriteOnOu_ThenSEC081Fires` (via_broad_write), `WhenPrincipalHasLinkGpoOnOu_ThenSEC081EmitsFullShape` (specific), and `WhenPrincipalHasBothSpecificAndBroadLinkOnOu_ThenSEC081PrefersSpecific`. **Note:** the broad OU-write capability for *named* (non-broad, non-admin) principals is otherwise uncovered — SEC-060 fires only for broad principals — so SEC-081 is currently the only rule surfacing those 1039; a dedicated "dangerous container control" rule is tracked separately (see lab investigation).
2. `[IMP-TGT-CLASS]` — **RESOLVED (coupled with `[IMP-CTRL-SCOPE]`).** Because the broad rights are class-agnostic, the widened set is gated on `o.object_class IN ('organizationalUnit', 'domainDNS', 'site')` so a broad grant on a non-container (e.g. a user) cannot fire "can link GPO". Pinned by `WhenGenericAllOnUserNotContainer_ThenSEC081DoesNotFire`.
3. `[IMP-DEL-OBJ]` — Add `AND o.is_deleted = 0` to the evaluator SQL. Without it, a non-admin who held gPLink write on a tombstoned OU still surfaces a finding even though the OU no longer applies. Same family-wide gap as SEC-080.
4. `[IMP-DN-ENRICH]` — `Detail` and `ContextJson` carry the source SID but no display name / SAM account name. Join `dim_principal` (or `dim_object` on `sid`) and surface `source_name` next to `source_sid`.
5. `[IMP-PRIV-MEMB-SRC]` — A principal transitively a Domain Admin still fires SEC-081 even though they are admin-equivalent. Decide whether SEC-081 should exclude `source_is_privileged_by_membership = true` (consistent with the admin-source skip) or keep them but tier severity differently. Mirrors the SEC-080 / SEC-024 / SEC-025 family.
6. `[IMP-PRIV-PROV]` — `ContextJson` exposes `source_is_privileged_by_membership` but no provenance — which privileged group(s) the source reaches. Extend `RuleEvaluationContext.PrivilegedSidProvenance` (per the existing IMP entry) and surface it.
7. `[IMP-PARITY-TEST]` — `RuleCatalogParityTests` does not assert SEC-081 severity / category / MITRE / tags. Add an explicit per-rule parity test mirroring the pattern used for SEC-070..SEC-077.
8. `[IMP-CAT-WORDING]` — Catalog `description` says "link GPOs to OUs via write access to the gPLink attribute". The rule also fires on `LinkGPO` edges against the domain root and (potentially) sites. Tighten the catalog wording to "OUs, sites, or the domain root" so the user-facing description matches the evaluator and the AD schema.
9. **GPO-link enforcement.** `gPLink` is an attribute on the container, not on the GPO. A principal who can link an attacker-controlled GPO into an OU but cannot modify the GPO is partly covered by SEC-081 alone; combined with SEC-080 it is a complete escalation. Consider correlating SEC-080 / SEC-081 in the escalation-path output or surfacing a derived `gpo_link_escalation` finding at higher severity when the same SID holds both edges. Out of scope for SEC-081 itself; logged here for product-level awareness.
