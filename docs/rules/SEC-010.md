## 2. Intended detection (plain English)

A finding must be raised for every captured account (any class — user, computer, gMSA, …) that has the `TRUSTED_FOR_DELEGATION` flag (`userAccountControl & 0x80000`) set, **except** when the account is itself a Domain Controller computer (where unconstrained delegation is expected and benign). Severity is `High`.

### 3.1 Effective SQL

```sql
SELECT o.object_guid, o.distinguished_name, o.object_class, o.sid
FROM dim_delegation d
INNER JOIN dim_object o ON d.object_guid = o.object_guid
WHERE d.delegation_type = 'Unconstrained'
ORDER BY o.sid, o.object_guid
```

The `'Unconstrained'` literal is the upstream string written by `DirectObjectWriter.WriteDelegations` whenever `userAccountControl & TrustedForDelegation` (`0x80000`) is set on the captured object.

### 3.2 Post-SQL filters (in C#)

1. **Domain Controller skip** — emitted rows are dropped when **both**:
   - `object_class.Equals("computer", OrdinalIgnoreCase)`, AND
   - `distinguished_name?.Contains("OU=Domain Controllers", OrdinalIgnoreCase) == true`.

   No other exclusions are applied (no admin-source skip, no broad-SID skip, no privileged-target check, no `is_deleted` filter, no `deny_cancelled` semantics — `dim_delegation` does not have a deny channel).

### 3.3 Finding shape

- `RuleId == "SEC-010"`, `Severity == Severity.High` (resolved via `SeverityOf` â†’ `BuiltInRules.ById["SEC-010"].DefaultSeverity`).
- `SubjectSid` = `o.sid` if non-null, else `""`.
- `TargetKind == "object_guid"`, `TargetId` = `o.object_guid` in `D` format.
- `FindingKey == "SEC-010|{SubjectSid}|{TargetId}"`.
- `Detail` = `"Unconstrained delegation on {dn ?? guid}"`.
- `ContextJson` keys: `evidence_type = "delegation"`, `delegation_type = "Unconstrained"`, `object_dn`, `object_class`, `object_guid`.

### 3.4 Relationship to SEC-011

`SEC-011` ("Unconstrained Delegation on Non-DC", `Critical`) is the **computer-class** half of a clean partition. [IMP-DUP-RULE] (resolved): the two evaluators previously ran identical SQL, so every non-DC unconstrained-delegation principal fired both. They are now partitioned on `object_class` — SEC-010 fires only when `object_class != 'computer'` (users, gMSAs, managed service accounts, … at `High`), and SEC-011 fires only when `object_class = 'computer'` (at `Critical`, where TGT capture has direct lateral-movement value). Each non-DC principal therefore fires **exactly one** of the two rules. See Â§12 and Â§13.

## 5. Exclusions (and the reason each is correct)

| Exclusion | Mechanism | Justification |
| --- | --- | --- |
| Computer accounts (any non-DC computer) | SQL `o.object_class != 'computer'` | `[IMP-DUP-RULE]`: computer-class principals are the higher-severity SEC-011 case. Partitioning here makes SEC-010 / SEC-011 non-overlapping. |
| Domain Controller computer accounts | `RuleEvaluatorHelpers.IsDomainControllerSql` (subsumed by the computer-class exclusion above) | Domain Controllers are expected to be `TRUSTED_FOR_DELEGATION`; flagging them is noise. |

Not excluded (intentionally subject to review):

- **Deleted objects** — `dim_object.is_deleted` is not filtered. A tombstoned account whose pre-deletion `userAccountControl` had `TRUSTED_FOR_DELEGATION` would still fire if the row remains in `dim_delegation`. Documented as `[IMP-DEL-OBJ]`.
- **Disabled accounts** — `userAccountControl & ACCOUNTDISABLE` is not consulted by SEC-010. A disabled account with the flag still fires. Arguably correct (the flag is a configuration defect even on disabled accounts) but worth flagging.
- **Read-only / RODC / partial-replica DCs** — caught only if their DN contains `OU=Domain Controllers`. A DC parked under a custom OU (or a writable DC moved out of the default container) is **not** excluded. Documented as `[IMP-DC-DETECT]`.
- **Non-DC `computer` accounts whose DN incidentally contains the substring** (e.g., `CN=DCAudit,OU=Operations Domain Controllers Project,...`) are **incorrectly excluded** by the heuristic. Documented as `[IMP-DC-DETECT]`.
- **Privileged-by-membership principals as the subject** — the rule does not classify the subject (the account itself) by membership; severity is `High` flat regardless of whether the account is in Domain Admins / Tier-0. This is the proper scope of SEC-131 (`WhenPrivilegedAccountWithUnconstrained_ThenSEC131Fires`), which already exists. No defect here.

## 12. Defects / deferred items

> Improvement tags follow the taxonomy in `docs/rules/IMPROVEMENTS.md`.

1. `[IMP-DC-DETECT]` **DC detection is a fragile DN-LIKE heuristic.** The post-SQL filter requires `object_class == "computer"` **and** `distinguished_name` to contain the substring `"OU=Domain Controllers"`. This (a) **misses DCs** parked in a non-default OU or under nested OUs that don't include the literal substring, and (b) **false-positives** any computer whose DN matches the substring at an OU boundary — most concretely, a non-DC host under an OU whose name starts with `"Domain Controllers"` (e.g., `OU=Domain Controllers Audit`). The robust signal is `userAccountControl & 0x2000` (`SERVER_TRUST_ACCOUNT`) for full DCs (and `0x4000` for RODCs), optionally combined with `primaryGroupID == 516`. **Status: deferred improvement.** Resolution: introduce a shared `RuleEvaluatorHelpers.IsDomainController(...)` helper, then update SEC-010, SEC-011, SEC-012 to use it. Affects three rules — appropriate for a themed pass.
2. `[IMP-DUP-RULE]` **RESOLVED — partitioned on `object_class`.** SEC-010 and SEC-011 previously ran byte-for-byte identical SQL (`delegation_type = 'Unconstrained' AND NOT IsDomainController`), so every non-DC unconstrained-delegation principal produced two findings (`High` + `Critical`). Per a product decision (option b), the rules now partition cleanly on `object_class`: SEC-010 adds `AND o.object_class != 'computer'` (non-computer principals, `High`); SEC-011 adds `AND o.object_class = 'computer'` (computer principals, `Critical`). `object_class` is `TEXT NOT NULL` in `dim_object`, so no NULL handling is required. Each non-DC principal now fires exactly one rule. Pinned by `WhenComputerHasUnconstrained_ThenOnlySEC011Fires`, `WhenNonComputerHasUnconstrained_ThenOnlySEC010Fires`, and the converted per-class tests.
3. `[IMP-DEL-OBJ]` **`is_deleted` not filtered.** A tombstoned object whose `dim_delegation` row remains would still fire. **Status: accepted-with-known-limitation.** Identical shape to SEC-001/SEC-003/SEC-004/SEC-005/SEC-006 Â§12; shared resolution.
4. `[IMP-DN-ENRICH]` **`Detail` does not include display name / sAMAccountName.** Only the DN is rendered. **Status: accepted-with-known-limitation.** Shared with SEC-001/003/004/005/006.
