```yaml
- id: SEC-012
  name: "Constrained Delegation to Sensitive Service"

    An account has constrained delegation to a sensitive service (LDAP, KRBTGT, or CIFS/HOST on a Domain Controller).
  severity: High
  category: Delegation
  remediation: >-
    Review delegation targets and remove sensitive service SPNs.
  mitre: T1558.001
  tags: ["kerberos", "delegation", "constrained"]
```

Source: `src/SecureAD.Core/Findings/Rules/rules.yaml` lines 91–100.

## 2. Intended detection (plain English)

A finding must be raised for every captured account that has constrained delegation (Kerberos S4U2Proxy via `msDS-AllowedToDelegateTo`) to at least one **sensitive** service principal name (SPN):

- Any `ldap/...` SPN — confers DCSync-equivalent access if used against a DC.
- Any `krbtgt/...` SPN — confers TGT-forging-adjacent capability.
- Any `cifs/...` or `host/...` SPN **where the target hostname matches a Domain Controller's CN** — confers silver-ticketing against the DC.

Catalog severity is `High`. The catalog description matches the code's three sensitivity classes.

### 3.1 Effective SQL

```sql
SELECT o.object_guid, o.distinguished_name, o.sid, d.target
FROM dim_delegation d
INNER JOIN dim_object o ON d.object_guid = o.object_guid
WHERE d.delegation_type = 'Constrained'
  AND (
    d.target LIKE 'ldap/%' OR d.target LIKE 'krbtgt/%'
    OR (
      (d.target LIKE 'cifs/%' OR d.target LIKE 'host/%')
      AND EXISTS (
        SELECT 1 FROM dim_object dc
        WHERE dc.object_class = 'computer'
          AND dc.user_account_control & 8192 = 8192
          AND (
            UPPER(SUBSTR(d.target, INSTR(d.target, '/') + 1)) =
              UPPER(SUBSTR(dc.distinguished_name, 4, INSTR(dc.distinguished_name, ',') - 4))
            OR
            UPPER(SUBSTR(d.target, INSTR(d.target, '/') + 1,
              CASE WHEN INSTR(SUBSTR(d.target, INSTR(d.target, '/') + 1), '.') > 0
                   THEN INSTR(SUBSTR(d.target, INSTR(d.target, '/') + 1), '.') - 1
                   ELSE LENGTH(d.target)
              END)) =
              UPPER(SUBSTR(dc.distinguished_name, 4, INSTR(dc.distinguished_name, ',') - 4))
          )
      )
    )
  )
ORDER BY o.sid, o.object_guid
```

Decoded:
- `delegation_type = 'Constrained'` rows are written by `DirectObjectWriter.WriteDelegations` for each entry in `msDS-AllowedToDelegateTo`.
- **`ldap/%` / `krbtgt/%`** — sensitive regardless of target host.
- **`cifs/%` / `host/%`** — sensitive only if the post-slash host part matches the CN of a captured **Domain Controller**. DC-ness is detected via `dc.user_account_control & 8192 = 8192` (= `0x2000` = `SERVER_TRUST_ACCOUNT`). This is the **robust UAC-based DC detection** that `[IMP-DC-DETECT]` recommends for SEC-010/SEC-011 — SEC-012 is the model.
- DC short-name extraction: `SUBSTR(dn, 4, INSTR(dn, ',') - 4)` takes everything between position 4 (after `CN=`) and the first comma. Assumes a `CN=...,` prefix, which holds for AD computer DNs.
- SPN host comparison: either whole-match (`cifs/dc01` vs `CN=DC01`) or dotted-prefix match (`cifs/dc01.test.local` â†’ `dc01` vs `DC01`). Both sides upper-cased.

### 3.3 Finding shape

- `RuleId == "SEC-012"`, `Severity == Severity.High` (resolved via `SeverityOf` â†’ `BuiltInRules`).
- `SubjectSid` = `o.sid` if non-null, else `""`.
- `TargetKind == "object_guid"`, `TargetId` = the *subject* object's GUID (the account holding the delegation), in `D` format. There is no separate target-object identity for SEC-012 — the SPN itself is the conceptual target but is not modelled as an object GUID.
- `FindingKey == "SEC-012|{SubjectSid}|{TargetId}"` — **does not include `d.target`**. Combined with `INSERT OR IGNORE` in `InsertFinding`, this means an account constrained-delegated to multiple sensitive SPNs (e.g. both `ldap/dc01` and `cifs/dc01`) produces **only one** persisted finding. The first SPN's `Detail` / `delegation_target` wins. See `[IMP-KEY-COLLAPSE]` in Â§12.
- `Detail` = `"Constrained delegation to sensitive service {target} on {dn ?? guid}"`.
- `ContextJson`: `evidence_type = "delegation"`, `delegation_type = "Constrained"`, `delegation_target = {SPN}`, `object_dn`, `object_guid`.

### 3.4 Sensitive-SPN scope

| Pattern | Always fires? | Why |
| --- | --- | --- |
| `ldap/%` | Yes | Any LDAP delegation is sensitive (DCSync-equivalent against a DC; potential confused-deputy elsewhere). |
| `krbtgt/%` | Yes | Conceptually delegation against the KDC ticket-granting service. |
| `cifs/%` or `host/%` on a DC | Yes (if host matches a DC CN) | Enables silver-ticket on the DC. |
| `cifs/%` or `host/%` on a non-DC | No | Out of scope — intentional. |
| Any other SPN (`HTTP/`, `MSSQLSvc/`, `TERMSRV/`, etc.) | No | Out of scope — intentional. |

## 5. Exclusions (and the reason each is correct)

| Exclusion | Mechanism | Justification |
| --- | --- | --- |
| Non-constrained delegation rows (`Unconstrained`, `RBCD`, `SPN`, `AdminCount`, …) | SQL `delegation_type = 'Constrained'` | Out of scope — covered by SEC-010/011/013/etc. |
| Constrained delegation to non-sensitive SPNs (`HTTP/...`, `MSSQLSvc/...`, etc.) | SQL OR-chain on `ldap/%`, `krbtgt/%`, `cifs/%`, `host/%` | Constrained delegation to a generic service is not the sensitive class. |
| `cifs/%` or `host/%` to a non-DC host | Inner `EXISTS` clause gates on `user_account_control & 0x2000` | Silver-ticket risk only applies on a DC. |

Not excluded (intentionally subject to review):

- **Deleted objects** — `is_deleted` not filtered. `[IMP-DEL-OBJ]`.
- **Disabled accounts** — `userAccountControl & ACCOUNTDISABLE` not consulted.
- **Cross-realm `krbtgt/REALM`** — legitimate trust artefact, but matched by `krbtgt/%`. Intentional; this is genuinely sensitive.
- **`ldap/<non-DC>`** — fires even though the target host is not a DC. Intentional; LDAP on non-DC is rare and high-signal.

## 12. Defects / deferred items

> Improvement tags follow the taxonomy in `docs/rules/IMPROVEMENTS.md`.

1. `[IMP-KEY-COLLAPSE]` **`FindingKey` did not include the SPN target.** **Status: RESOLVED.** An account constrained-delegated to multiple sensitive SPNs (e.g. both `ldap/dc01` and `cifs/dc01`) previously produced **only one** persisted finding due to `INSERT OR IGNORE` on `(run_id, finding_key)` — the remaining SPN findings were silently dropped, losing remediation evidence and undercounting. `CreateDelegationFinding` now accepts an optional `findingKeyDiscriminator`; SEC-012 passes the SPN `target`, so the key becomes `SEC-012|{subject}|{guid}|{spn}` and each sensitive SPN persists its own finding. Pinned by `WhenConstrainedDelegationToMultipleSensitiveSpns_ThenSEC012FiresPerSpn`.
2. `[IMP-SPN-PARSE]` **SQL SPN parsing fails for `service/host:port` with no dot.** **Status: RESOLVED.** The previous dual-branch `INSTR`/`SUBSTR` host match returned the full post-slash substring (including `:port`) whenever the host had no dot, so `cifs/dc01:445` against `CN=DC01,...` was a false negative. Replaced with the shared `RuleEvaluatorHelpers.ShortSpnHostSql(column)` fragment, which normalizes the SPN host in one pass — substring after `/`, strip a trailing `:port`, then strip the DNS suffix — and compares the result for equality against the DC's leading CN. The host-match clause is now a single `UPPER(ShortSpnHostSql(d.target)) = UPPER(<DC short CN>)` equality instead of the two-branch OR. Pinned by `WhenConstrainedDelegationCifsWithPortAndNoDot_ThenSEC012Fires` and `WhenConstrainedDelegationCifsWithPortAndDot_ThenSEC012Fires`.
3. `[IMP-DEL-OBJ]` **`is_deleted` not filtered.** Tombstoned objects with a `dim_delegation` row would still fire. **Status: accepted-with-known-limitation.** Shared resolution with the SEC-001…SEC-011 cluster.
4. `[IMP-DN-ENRICH]` **`Detail` does not include display name / sAMAccountName.** **Status: accepted-with-known-limitation.** Shared.
