## 1. Catalog claim (verbatim from `rules.yaml`)

```yaml
- id: SEC-024
  name: "Unexpected Principal can Write SPN"
  description: >-
    A principal can write servicePrincipalName, which can enable targeted Kerberoasting.
  severity: High
  category: CredentialTheft
  remediation: >-
    Remove write access to SPN attribute unless the delegation is explicitly required and documented.
  mitre: T1558.003
  tags: ["kerberos", "kerberoasting", "spn-write"]
```

Source: `src/SecureAD.Core/Findings/Rules/rules.yaml` lines 168–177.

## 2. Intended detection (plain English)

A finding must be raised for every non-admin principal that holds a
`WriteSPN` control edge on a target object whose effective ACL was not
overridden by an explicit deny. The attack vector is targeted
Kerberoasting: an attacker writes a service SPN onto a victim account
(typically a user with a known-weak password) and then requests a TGS
for that SPN to harvest a crackable hash. The catalog's stated severity
is `High` but the evaluator escalates to `Critical` when the **target**
SID resolves to a well-known high-value principal (Domain Admins,
krbtgt, Enterprise Admins, Schema Admins, Domain Controllers,
BUILTIN\\Administrators, etc.), since rewriting the SPN of a tier-zero
account is materially worse than the equivalent on a generic account.

### 3.1 Effective SQL (copied from code)

```sql
SELECT e.source_sid, e.target_object_guid, o.distinguished_name, e.edge_id, o.sid AS target_sid
FROM fact_control_edge e
INNER JOIN dim_object o ON e.target_object_guid = o.object_guid
WHERE e.control_type = 'WriteSPN' AND e.deny_cancelled = 0
ORDER BY e.source_sid, e.target_object_guid
```

### 3.2 Post-SQL filters (in C#)

- `if (RuleEvaluatorHelpers.IsAdminSid(sid)) continue;` — the **only**
  source-side filter. `IsAdminSid` matches RIDs in `AdminRids` =
  {500, 502, 512, 516, 518, 519, 520, 521, 526, 527} as well as
  `PrivilegedSystemSids`, but explicitly returns `false` for
  `BroadSids` (`S-1-1-0`, `S-1-5-11`, `S-1-5-7`). Broad principals
  therefore **still fire** SEC-024 — same posture as SEC-001.
- Severity escalation: `WellKnownSidCatalog.IsHighValue(targetSid) ?
  Severity.Critical : Severity.High`. `IsHighValue` is keyed on the
  catalog's `IsHighValue` flag, set for BUILTIN\\Administrators
  (`S-1-5-32-544`), Account Operators (`-548`), Server Operators
  (`-549`), Print Operators (`-550`), Backup Operators (`-551`), and
  the domain-relative templates Administrator (`-500`), krbtgt
  (`-502`), Domain Admins (`-512`), Domain Controllers (`-516`),
  Schema Admins (`-518`), Enterprise Admins (`-519`).
  `[IMP-HV-CAT]` (resolved) aligned this set with `IsTierZeroFallbackSid`
  and `HighValueTargets` so RID 500 and Print Operators are now
  high-value (a WriteSPN edge onto the literal Administrator account
  surfaces as `Critical`).
- `ContextJson` includes a `source_admin_classification` field via
  `ClassifyPrincipal`: `WellKnownAdmin` / `PrivilegedByMembership` /
  `BroadPrincipal` / `SystemOrExpectedBuiltIn` / `NonPrivileged`.

## 9. Output assertions (`Detail` and `ContextJson`)

The finding produced must include:

- `RuleId == "SEC-024"`
- `Severity == High` (default) or `Critical` (when `IsHighValue(targetSid)` is true)
- `SubjectSid` = the source's SID (non-empty)
- `TargetKind == "object_guid"`
- `TargetId` = target object GUID (`D` format)
- `SourceEdgeId == e.edge_id` (non-null when the edge has an id)
- `FindingKey == "SEC-024|{SubjectSid}|{TargetId}"`
- `Detail` matches `Principal {sid} can write SPNs on {targetDn ?? guid}. This can enable targeted Kerberoasting or service identity abuse.`
- `ContextJson` non-null and contains:
  - `"rule_id": "SEC-024"`
  - `"source_sid": "<sourceSid>"`
  - `"target_guid": "<GUID in D format>"`
  - `"target_dn": "<DN or null>"`
  - `"control_type": "WriteSPN"`
  - `"edge_id": <long or null>`
  - `"evidence_type": "control_edge"`
  - `"source_admin_classification": "NonPrivileged" \| "BroadPrincipal" \| "PrivilegedByMembership" \| "WellKnownAdmin" \| "SystemOrExpectedBuiltIn" \| "Unknown"`
  - `"source_is_well_known_admin": false` (always false here because `IsAdminSid` already filtered out admin sources)
  - `"source_is_privileged_by_membership": <bool>`
  - `"source_is_broad_principal": <bool>`

## 12. Defects / deferred items

1. `[IMP-CTRL-SCOPE]` — **RESOLVED.** SEC-024 previously filtered
   strictly on `control_type = 'WriteSPN'`, missing principals who can
   write `servicePrincipalName` via a broad grant (capture tags such an
   ACE `GenericAll` / `GenericWrite` / `WriteAllProperties`, never the
   specific `WriteSPN`). `EvaluateWriteSpn` now matches the property-write
   equivalence set `RuleEvaluatorHelpers.PropertyWriteEquivalents(WriteSPN)`
   = `{WriteSPN, GenericAll, GenericWrite, WriteAllProperties}` and surfaces
   the actual matched `control_type` (via `MIN(control_type)` over a
   `GROUP BY`). The DACL-pivot rights (`WriteDacl` / `WriteOwner`) are
   intentionally excluded — they are SEC-004 / SEC-005's domain. Pin
   `WhenNoWriteSpnEdgeExists_ThenSEC024DoesNotFire` was flipped to
   `WhenGenericWriteOnUserTarget_ThenSEC024Fires`.

2. `[IMP-TGT-CLASS]` — **RESOLVED (coupled with `[IMP-CTRL-SCOPE]`).**
   Because the broad rights above are class-agnostic, widening without a
   target-class filter would fire "can write SPNs" on a group or OU. The
   SQL now constrains `o.object_class IN ('user', 'computer',
   'msDS-GroupManagedServiceAccount')`. Pinned by
   `WhenGenericAllOnGroupTarget_ThenSEC024DoesNotFire`. (Note:
   `msDS-ManagedServiceAccount` (sMSA) was not added — no test fixture
   exercises it; add it if sMSA SPN-write coverage is required.)

3. `[IMP-DEL-OBJ]` — The SQL joins `dim_object` without filtering
   `is_deleted = 1`. A tombstoned target with a stale `WriteSPN` edge
   still fires.

4. `[IMP-PRIV-MEMB-SRC]` — `IsAdminSid` only matches well-known RIDs
   and `PrivilegedSystemSids`. A user transitively in Domain Admins via
   nested groups but without a `-512` RID directly is **not** excluded
   and will fire SEC-024. `ContextJson` reports
   `source_admin_classification = "PrivilegedByMembership"` so the
   downstream UI can de-prioritise, but the finding still surfaces.
   Same posture as SEC-001 Â§E8.

5. `[IMP-DN-ENRICH]` — `ContextJson` carries `target_dn` and
   `source_sid` but no `sam_account_name` or display name for either
   side; cross-domain SIDs and renamed objects are hard to triage
   without a reverse lookup.

6. `[IMP-HV-CAT]` — **RESOLVED.** `WellKnownSidCatalog` previously
   marked domain-relative RID 500 (built-in `Administrator`) as **not**
   high-value, so a non-admin source writing SPNs onto the literal
   RID-500 account surfaced as `High` instead of `Critical`. Audited the
   catalog's `IsHighValue` flags against the codebase's other Tier-0
   authorities (`EscalationPathRuleEvaluator.IsTierZeroFallbackSid` =
   `{500, 502, 512, 516, 518, 519}` and `HighValueTargets.AdminUserRids`
   = `{500, 502}`) and flipped two flags to `true`: domain-relative RID
   500 (Administrator) and `S-1-5-32-550` (`BUILTIN\Print Operators`,
   which was inconsistent with its three AdminSDHolder sibling operator
   groups 548 / 549 / 551). Bumped `CatalogVersion` 2 â†’ 3. Pinned by the
   expanded `WellKnownSidCatalogTests` high-value theories /
   `WhenHighValueEntries_ThenMatchSpec` and by
   `WhenWriteSpnTargetIsBuiltinAdministrator_ThenSEC024IsCritical`.

7. `[IMP-PARITY-TEST]` — No per-rule severity / MITRE / tag parity
   assertion exists for SEC-024 in `RuleCatalogParityTests`. Adding
   one (`Severity == High`, `mitre == "T1558.003"`, tags `{
   "kerberos", "kerberoasting", "spn-write" }`) would prevent silent
   catalog edits. Note: the parity test should assert the **catalog**
   severity (High); the per-finding Critical escalation lives in the
   evaluator and is tested via P2 / P5.

8. `[IMP-CAT-WORDING]` — The catalog description does not mention the
   severity escalation on high-value targets. A reader following the
   catalog will not know that SEC-024 can surface as `Critical`.
   Suggested resolution: extend the description to "*… targeted
   Kerberoasting. Escalated to Critical when the target is a
   well-known privileged principal (Domain Admins, krbtgt, Enterprise
   Admins, etc.).*"
