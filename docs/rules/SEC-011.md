## 2. Intended detection (plain English)

A finding must be raised for every captured **computer-class** account that has the `TRUSTED_FOR_DELEGATION` flag (`userAccountControl & 0x80000`) set, **except** when the account is itself a Domain Controller (where unconstrained delegation is expected and benign). Severity is `Critical` — computer principals are the higher-severity half of the SEC-010 / SEC-011 partition because a compromised host with unconstrained delegation has direct lateral-movement value. Non-computer principals (users, gMSAs, …) are the SEC-010 (`High`) case; `[IMP-DUP-RULE]` (resolved) partitions the two rules on `object_class` so each non-DC principal fires exactly one.

### 3.1 Effective SQL

```sql
SELECT o.object_guid, o.distinguished_name, o.object_class, o.sid
FROM dim_delegation d
INNER JOIN dim_object o ON d.object_guid = o.object_guid
WHERE d.delegation_type = 'Unconstrained'
  AND NOT (o.object_class = 'computer'
      AND o.distinguished_name LIKE '%OU=Domain Controllers%')
ORDER BY o.sid, o.object_guid
```

`'Unconstrained'` is the literal written by `DirectObjectWriter.WriteDelegations` when `userAccountControl & TrustedForDelegation` (`0x80000`) is set. SQLite `LIKE` defaults to ASCII case-insensitive matching (no `case_sensitive_like` pragma is set anywhere in the schema), so `LIKE '%OU=Domain Controllers%'` matches `ou=domain controllers`, `OU=DOMAIN CONTROLLERS`, etc., for ASCII characters — equivalent to SEC-010's `Contains(OrdinalIgnoreCase)` for any realistic DN.

## 5. Exclusions (and the reason each is correct)

| Exclusion | Mechanism | Justification |
| --- | --- | --- |
| Computer accounts whose DN contains `OU=Domain Controllers` (ASCII case-insensitive) | SQL `NOT (object_class = 'computer' AND DN LIKE '%OU=Domain Controllers%')` | Domain Controllers are expected to be `TRUSTED_FOR_DELEGATION`; flagging them is noise. |

Not excluded (intentionally subject to review):

- **Deleted objects** — `dim_object.is_deleted` is not filtered. `[IMP-DEL-OBJ]`.
- **Disabled accounts** — not consulted. A disabled account with the flag still fires.
- **Read-only / RODC / non-default-OU DCs** — caught only if their DN contains the substring. `[IMP-DC-DETECT]` (same as SEC-010).
- **Non-DC computers parked under an OU whose name begins with `Domain Controllers`** (e.g., `OU=Domain Controllers Audit`) are **incorrectly excluded** by the heuristic. `[IMP-DC-DETECT]`.
- **Privileged-by-membership principals as the subject** — out of scope for SEC-011 (handled by SEC-131).

## 9. Output assertions (`Detail` and `ContextJson`)

The finding produced must include:

- `RuleId == "SEC-011"`
- `Severity == Severity.Critical`
- `SubjectSid` = `dim_object.sid` (empty string when null)
- `TargetKind == "object_guid"`
- `TargetId` = `object_guid` in `D` format
- `FindingKey == "SEC-011|{SubjectSid}|{TargetId}"`
- `Detail` contains `"Non-DC account with unconstrained delegation: "` followed by the DN (or GUID when DN is null)
- `ContextJson` is non-null and contains:
  - `"evidence_type": "delegation"`
  - `"delegation_type": "Unconstrained"`
  - `"object_dn"` matches the source DN (or null)
  - `"object_class"` matches the captured class
  - `"domain_controller": false`
  - `"object_guid"` matches the GUID in `D` format

## 12. Defects / deferred items

> Improvement tags follow the taxonomy in `docs/rules/IMPROVEMENTS.md`.

1. `[IMP-DUP-RULE]` **RESOLVED — partitioned on `object_class`.** SEC-010 and SEC-011 previously ran byte-for-byte identical SQL, so every non-DC unconstrained-delegation principal produced two findings. Per a product decision (option b), SEC-011 now adds `AND o.object_class = 'computer'` and SEC-010 adds `AND o.object_class != 'computer'`, so the two rules cover disjoint input and each non-DC principal fires exactly one. Mirror of `SEC-010.md` Â§12.2. Pinned by `WhenComputerHasUnconstrained_ThenOnlySEC011Fires`, `WhenNonComputerHasUnconstrained_ThenOnlySEC010Fires`, `WhenUserHasUnconstrainedDelegation_ThenSEC011DoesNotFire`, and `WhenGmsaHasUnconstrainedDelegation_ThenSEC011DoesNotFire`.
2. `[IMP-DC-DETECT]` **DC detection is a fragile DN-LIKE heuristic.** The SQL filter requires `object_class = 'computer'` **and** `distinguished_name LIKE '%OU=Domain Controllers%'`. (a) Misses DCs parked in non-default OUs. (b) False-positives non-DC computers under an OU whose name *begins* with `Domain Controllers`. **Status: deferred improvement.** Mirror of `SEC-010.md` Â§12.1; the shared `IsDomainController(...)` helper fix resolves SEC-010, SEC-011, and SEC-012 together.
3. `[IMP-DEL-OBJ]` **`is_deleted` not filtered.** Tombstoned objects with a `dim_delegation` row would still fire. **Status: accepted-with-known-limitation.** Shared resolution with SEC-001/003/004/005/006/010.
4. `[IMP-DN-ENRICH]` **`Detail` does not include display name / sAMAccountName.** **Status: accepted-with-known-limitation.** Shared resolution with the SEC-001…SEC-010 cluster.
