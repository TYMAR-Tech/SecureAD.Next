## 1. Catalog claim (verbatim from `rules.yaml`)

```yaml
- id: SEC-001
  name: "Unexpected GenericAll on Domain"
  description: >-
    A principal outside the expected domain control set has GenericAll (full control) over the domain object.
  severity: Critical
  category: DangerousPermissions
  remediation: >-
    Remove GenericAll permission unless the delegation is explicitly required and documented.
  mitre: T1098
  tags: ["tier-zero", "domain-control"]
```

Source: `src/SecureAD.Core/Findings/Rules/rules.yaml` lines 3–12.

## 2. Intended detection (plain English)

A finding must be raised for every captured `GenericAll` (full control) right that points at the domain root object (object class `domainDNS`) and whose source principal is **not** a well-known admin / system principal. The rule's purpose is to surface direct domain takeover paths granted to non-admins.

### 3.1 Effective SQL (from `EvaluateControlEdgeRule`)

```sql
SELECT e.source_sid, e.target_object_guid, o.distinguished_name, e.edge_id
FROM fact_control_edge e
INNER JOIN dim_object o ON e.target_object_guid = o.object_guid
WHERE e.control_type = $type AND e.deny_cancelled = 0
AND object_class = 'domainDNS'
ORDER BY e.source_sid, e.target_object_guid, e.control_type
```

`$type` is bound to `ControlType.GenericAll.ToString()` → `"GenericAll"`.

### 3.2 Post-SQL filters (in C#)

- `excludeAdmins = true` → rows where `IsAdminSid(source_sid)` is true are skipped (`RuleEvaluatorHelpers.cs:579`).
- `IsAdminSid` is true when the SID is in `PrivilegedSystemSids` **or** ends in one of `{500, 502, 512, 516, 518, 519, 520, 521, 526, 527}`. It explicitly returns `false` for `BroadSids` (`S-1-1-0`, `S-1-5-11`, `S-1-5-7`).

## 5. Exclusions (and the reason each is correct)

| Exclusion | Mechanism | Justification |
| --- | --- | --- |
| Deny-cancelled edges | `WHERE e.deny_cancelled = 0` | The right is not effective; flagging it would be a false positive. |
| Well-known admin RIDs (500, 502, 512, 516, 518, 519, 520, 521, 526, 527) | `IsAdminSid` via RID check | These principals are expected to hold full control over the domain root. |
| Well-known system SIDs (`S-1-5-18`, `S-1-5-9`, `S-1-3-0`, `S-1-5-10`, BUILTIN operator groups) | `IsAdminSid` via `PrivilegedSystemSids` | Same — expected built-ins. |

Not excluded (intentionally subject to review):

- **Broad principals** (`Everyone`, `Authenticated Users`, `Anonymous`) — `IsAdminSid` returns `false` for these, so they **will** fire SEC-001. SEC-060 also covers this; duplication is acceptable because SEC-001 carries higher signal for domain root.
- **Privileged-by-membership** principals (non-RID admins who are transitively in DA/EA) — `excludeAdmins` does not use `IsPrivilegedPrincipal`, so a user transitively in Domain Admins still fires.

## 9. Output assertions (`Detail` and `ContextJson`)

The finding produced must include:

- `RuleId == "SEC-001"`
- `Severity == Severity.Critical`
- `SubjectSid` = source principal SID from `fact_control_edge.source_sid`
- `TargetKind == "object_guid"`
- `TargetId` = target object GUID string (`D` format)
- `SourceEdgeId` = `fact_control_edge.edge_id` (non-null when capture stored it)
- `FindingKey == "SEC-001|{SubjectSid}|{TargetId}"`
- `Detail` contains substring `"GenericAll"` and the target DN (or GUID fallback)
- `ContextJson` is non-null and contains:
  - `"rule_id": "SEC-001"`
  - `"control_type": "GenericAll"`
  - `"evidence_type": "control_edge"`
  - `"source_admin_classification"` ∈ {`NonPrivileged`, `BroadPrincipal`, `PrivilegedByMembership`}
  - `"target_dn"` matches the target object's DN

## 12. Defects / deferred items

> Improvement tags follow the taxonomy in `docs/rules/IMPROVEMENTS.md`.

1. `[IMP-DEL-OBJ]` **`is_deleted` not filtered.** A `GenericAll` edge on a deleted (tombstoned) `domainDNS` object would still fire. **Status: accepted-with-known-limitation.** Capture upstream is expected to skip tombstoned objects; if a deleted domain root is captured at all, surfacing the finding is preferable to silent suppression. Re-open if real-world false positives appear.
2. `[IMP-DN-ENRICH]` **`Detail` does not include source display name.** Only the SID is rendered. **Status: accepted-with-known-limitation.** `ContextJson.source_admin_classification` plus the SID are sufficient for downstream UI/reporting to enrich with display names; no change required at the evaluator layer.
3. `[IMP-PRIV-MEMB-SRC]` **Privileged-by-membership not excluded** (see E8). Behaviour differs from SEC-201/204. **Status: accepted-with-known-limitation.** Intentional — SEC-001 is a domain-root takeover signal where any non-RID identity holding `GenericAll` (even one transitively in DA) deserves explicit attention; aligning with SEC-201/204 would suppress real signal. Documented; no change.
