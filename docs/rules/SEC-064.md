## 1. Catalog claim (verbatim from `rules.yaml`)

```yaml
- id: SEC-064
  name: "Dangerous User Right Granted via Group Policy"
  description: >-
    A Group Policy User Rights Assignment grants a sensitive privilege (such as SeDebugPrivilege,
    SeBackupPrivilege, SeRestorePrivilege, SeTakeOwnershipPrivilege, SeTcbPrivilege,
    SeLoadDriverPrivilege, SeEnableDelegationPrivilege, or SeImpersonatePrivilege) to a principal
    beyond its documented default holders. ... a grant to a broad principal is a direct escalation path.
  severity: High
  category: ConfigurationHygiene
  remediation: >-
    Confirm the privilege grant is an intended operational role. If not, remove the principal ...
  mitre: T1484.001
  tags: ["gpo", "user-rights", "privilege", "review", "sysvol"]
```

## 2. Intended detection (plain English)

A GPO's User Rights Assignment (`GptTmpl.inf [Privilege Rights]`, captured into `dim_gpo_setting`)
grants a **sensitive** privilege — one conferring a Tier-0-equivalent capability — to a principal
that is **not** one of that privilege's documented default holders, is **not** a well-known admin,
and is **not** a built-in system/service identity. These privileges (SeDebug, SeBackup, SeRestore,
SeTakeOwnership, SeTcb, SeCreateToken, SeLoadDriver, SeEnableDelegation, SeImpersonate, SeManageVolume,
SeSecurity, SeRelabel, SeTrustedCredManAccess, SeAssignPrimaryToken) are applied by policy to every
targeted computer and are invisible to directory group-membership rules.

Each grant is a **review** finding (`disposition = review_required`) because some are intended
operational roles (e.g. a backup team with `SeBackupPrivilege`). Severity:
- **Critical** when the holder is a **broad principal** (Everyone / Authenticated Users / Domain
  Users) — anyone gains the capability fleet-wide.
- **High** otherwise (a named non-admin beyond the documented baseline — review and confirm intent).

### 3.1 Effective SQL

```sql
SELECT s.gpo_guid, s.setting_key, s.setting_value, gpo.distinguished_name
FROM dim_gpo_setting s
INNER JOIN dim_object gpo ON s.gpo_guid = gpo.object_guid
WHERE s.source_file = 'GptTmpl.inf' AND s.section = 'Privilege Rights'
  AND s.setting_value IS NOT NULL AND TRIM(s.setting_value) != ''
ORDER BY s.gpo_guid, s.setting_key
```

### 3.2 Per-holder logic (in C#)

`setting_value` is `*SID,*SID,...` (the `*` marks a SID literal; `ParsePrivilegeHolders` strips it).
For each holder of a privilege that `UserRightCatalog.Find` classifies as sensitive:
1. Skip if the SID is a documented default holder for **that** privilege (`right.DefaultHolderSids`).
2. Skip if `ShouldExcludePrivilegedTrustee(sid, PrivilegedSids)` — well-known admin RIDs **and**
   principals transitively privileged via group closure (a named account that is a member of Domain
   Admins is already Tier-0, so the grant confers nothing new). Matches the SEC-063 exclusion.
3. Skip if `IsExpectedServiceSid(sid)` (System / Local Service / Network Service / Service /
   Creator Owner / Window Manager Group — built-in identities not present in the closure set).
4. Otherwise emit: `Critical` if `BroadPrincipalCatalog.IsBroad(sid)`, else `High`. FindingKey
   discriminator = `privilege|sid` (one finding per privilege per holder).

## 4. The sensitive-right catalog (grounded in Microsoft Security Baseline)

| Privilege | Baseline holders (default-holder SIDs) |
| --- | --- |
| SeTcbPrivilege, SeCreateTokenPrivilege, SeTrustedCredManAccessPrivilege, SeRelabelPrivilege | No One (empty) |
| SeDebugPrivilege, SeEnableDelegationPrivilege, SeTakeOwnershipPrivilege, SeManageVolumePrivilege, SeSecurityPrivilege | Administrators (544) |
| SeBackupPrivilege | Admins, Backup Ops, Server Ops (544/551/549) |
| SeRestorePrivilege | Admins, Backup Ops (544/551) |
| SeLoadDriverPrivilege | Admins, Print Ops (544/550) |
| SeImpersonatePrivilege | Admins, Service, Local/Network Service, System |
| SeAssignPrimaryTokenPrivilege | Local Service, Network Service (19/20) |

Source: Microsoft Windows Security Baseline — User Rights Assignment + Privilege Constants. Per-role
exactness (`=` vs `<=` vs `No One`) intentionally not modeled (out of v1 scope — see §11).

## 5. Exclusions (and why each is correct)

| Exclusion | Mechanism | Justification |
| --- | --- | --- |
| Non-sensitive privileges | `UserRightCatalog.Find` returns null | Only Tier-0-equivalent rights are in scope. **`SeChangeNotifyPrivilege` (Bypass traverse checking) is deliberately excluded** — Microsoft enables it for all users (incl. Everyone) by default; flagging it would be a guaranteed false positive. |
| Documented default holders | `right.DefaultHolderSids` | The secure baseline (e.g. `SeDebugPrivilege = Administrators`) must not fire. This is the lab's real config. |
| Well-known + transitively-privileged holders | `ShouldExcludePrivilegedTrustee` | Domain/Enterprise Admins, BUILTIN operator groups, **and** named accounts transitively privileged via group closure (`context.PrivilegedSids`) are expected to hold powerful privileges — the grant confers nothing new. Closure-aware, matching SEC-063. |
| System/service identities | `IsExpectedServiceSid` | System, Local/Network Service, Creator Owner, Window Manager Group hold privileges by design. |
| Non-Privilege-Rights rows | SQL `section = 'Privilege Rights'` | Registry.pol / other GptTmpl sections are out of scope. |

## 8. Output assertions

`ContextJson` carries `privilege`, `privilege_display_name`, `holder_sid`, `is_broad_principal`,
`disposition = "review_required"`, `vector = "user_rights_assignment"`. `Detail` leads "Review
privilege grant:". Severity `Critical` iff broad principal, else `High`. FindingKey is per
`SEC-064|<subject>|<gpoGuid>|<privilege>|<holderSid>`.

## 9. Disposition model

Same two-axis model as SEC-063: severity = impact (Critical for broad, High otherwise),
`disposition = review_required` = certainty (broad OU/privilege delegation is sometimes a supported
operational role, so confirm intent; if not what the org meant, it is the fix).

## 10. Live lab validation

Root + 2-child lab: **0 findings** (true negative). The captured `[Privilege Rights]` is the default
Default Domain Controllers Policy (`{6AC1786C-...}`) — every sensitive privilege is held only by
documented default / admin / system holders, and `SeChangeNotifyPrivilege = Everyone` is correctly
excluded as non-sensitive. Probe: `LabDbProbe.ValidateSec064_AgainstLab` (read-only, lab-only). The
member exclusion is closure-aware (`ShouldExcludePrivilegedTrustee`), so a named account that is a
transitive member of a privileged group is also suppressed (see N6). The positive path is pinned by
synthetic tests (§6); a lab non-default privilege grant to a genuinely non-privileged account will
exercise it end-to-end in a future capture.

## 11. Defects / deferred items

1. **Per-server-role / exact-match baseline** — v1 treats Administrators as always acceptable and
   uses a permissive union of default holders, so it does not flag e.g. `SeEnableDelegationPrivilege
   = Administrators` on a member server (baseline there is "No One"). This is a deliberate v1 scope
   choice (detect "someone dangerous holds this right", not full CIS benchmark). Deferred refinement.
2. **Friendly-name holders** — a privilege value with a non-`*` friendly name (rare; capture stores
   `*SID`) is surfaced for manual review rather than resolved. Acceptable (errs toward visibility).
3. `[IMP-DN-ENRICH]` — `holder_sid` is surfaced raw; a `dim_principal` join for `holder_name` would
   improve readability. Family-wide.
4. **GPO scope** — the finding names the GPO but not which computers/OUs it is linked to. Correlating
   with gPLink targets would let an operator gauge blast radius. Deferred enhancement.
