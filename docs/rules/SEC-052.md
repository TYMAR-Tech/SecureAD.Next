## 1. Catalog claim (verbatim from `rules.yaml`)

```yaml
- id: SEC-052
  name: "Circular Group Membership"
  description: >-
    Groups form a circular nesting loop where each group is transitively a member of itself. This breaks permission auditing, bloats Kerberos tokens, and makes group cleanup difficult.
  severity: Medium
  category: GroupMembership
  remediation: >-
    Removing any one direct group nesting link in the cycle will break the loop.
  tags: ["circular", "nested-groups", "cleanup"]
```

Source: `src/SecureAD.Core/Findings/Rules/rules.yaml` lines 273–281.

## 2. Intended detection (plain English)

Fire one finding per **strongly connected component (SCC)** in the directed graph
of direct group-in-group edges. The catalog phrasing "each group is transitively
a member of itself" means: a group whose `dim_object.object_class = 'group'`
participates in a cycle of `fact_group_membership_direct` rows where every
edge endpoint is itself a group. A single group that is a direct member of
itself counts as the degenerate 1-cycle. Severity is `Medium` by default, and
raised to `High` when any SID in the cycle is privileged (well-known admin RID
or member of the precomputed privileged set).

### 3.1 SQL: graph construction (groupâ†’group only)

```sql
SELECT DISTINCT g.group_sid, g.member_sid
FROM fact_group_membership_direct g
INNER JOIN dim_object og ON g.group_sid = og.sid AND og.object_class = 'group'
INNER JOIN dim_object om ON g.member_sid = om.sid AND om.object_class = 'group'
ORDER BY g.group_sid, g.member_sid
```

The inner-join on both sides with `object_class = 'group'` filter is what makes
the rule **direct, group-only**. Any user/computer on either endpoint silently
drops the edge from the graph. Missing `dim_object` rows likewise drop edges.

### 3.2 SQL: group name/GUID enrichment for `Detail`

```sql
SELECT sid, object_guid, distinguished_name
FROM dim_object
WHERE object_class = 'group' AND sid IS NOT NULL
ORDER BY sid
```

Used to map each SID in the cycle to a friendly name (`CN=` extracted up to the
first comma; otherwise the raw DN, otherwise the SID).

### 3.3 Algorithm

1. Build adjacency list `group_sid -> [member_sid, …]`.
2. Run iterative Tarjan to compute all SCCs.
   - SCCs of size > 1 are always emitted.
   - SCCs of size 1 are emitted **only** when the node has a self-edge.
3. For each emitted SCC, `ExtractRepresentativeCycle` chooses the
   lexicographically smallest SID as the anchor and BFS-extracts the shortest
   cycle through it, then canonicalizes the rotation + direction.
4. Severity is `High` if any SID in the SCC is privileged
   (`RuleEvaluatorHelpers.IsPrivilegedPrincipal`), otherwise `Medium`.
5. `FindingKey = "SEC-052|{sorted-SCC-SIDs joined by |}"`. **Note**: the key is
   the *full SCC*, not the chosen cycle path — so reordering or path-extraction
   changes never re-key the finding.

## 5. Exclusions (and the reason each is correct)

| Exclusion | Mechanism | Justification |
| --- | --- | --- |
| Edges with a non-group endpoint | `INNER JOIN dim_object … AND object_class = 'group'` on both sides | A user or computer cannot complete a group-nesting cycle; the rule is about group-to-group structure only. |
| Edges where either endpoint lacks a `dim_object` row | INNER JOIN drops the row | Without identity rows the rule cannot name or anchor the finding; treat as `Objects` coverage gap. |
| SCCs of size 1 with no self-edge | Tarjan output filter at lines 386–394 | Trivial SCCs are not cycles. |
| Transitive-only cycles | Only direct edges are loaded | The catalog scopes the loop to "direct" membership; transitive-only loops via the closure table would conflate distinct logical structures. |

Not excluded (intentionally subject to review):

- **Privileged groups in cycles** — emitted with `Severity = High` (correct).
- **Broad SIDs in cycles** — would still match if a broad SID had `object_class = 'group'`, but broad SIDs are non-domain principals so they never appear as a `dim_object` row with class `group` in practice.
- **Disabled or deleted groups** — `dim_object` has no `is_deleted` filter here. A disabled group still participates in the graph (intentional: an enabled cycle through a disabled link is still a cleanup risk).

## 12. Defects / deferred items

1. **Self-loop dropped by `cycle.Count < 2` guard — fixed in this card's commit.**
   `ExtractRepresentativeCycle` returns a 1-element list `[solo]` for size-1
   SCCs with a self-edge (the only kind Tarjan emits), but the consumer guard
   in `EvaluateCircularGroupMembership` immediately filtered those out. The
   catalog explicitly covers "each group is transitively a member of itself",
   and self-membership is a real-world cleanup-and-token-bloat case. Changed
   the guard to `cycle.Count < 1`. Resolved.

2. `[IMP-DEL-OBJ]` — Deleted/tombstoned groups still participate. Accepted: the
   captured `fact_group_membership_direct` rows are the ground truth at
   capture time; tombstones cannot be filtered out without a `dim_object`
   `is_deleted` flag.

3. `[IMP-PARITY-TEST]` — `RuleCatalogParityTests` covers the catalogâ†”evaluator
   mapping for SEC-052 generically but does not yet assert the specific
   `ContextJson` keys (`cycle`, `cycle_size`, `is_privileged`, `break_hint`).
   Accepted; per-key parity is handled by the shape test (Â§10).

## 13. Improvement suggestions (not blocking)

1. `[IMP-NAME-DERIVE]` — Name extraction at line 206–208 is a single-line
   `dn[3..dn.IndexOf(',')]`. For a DN that has no comma (rare but legal at the
   root, e.g. `CN=Group`) this would throw `ArgumentOutOfRangeException`
   because `IndexOf(',')` returns `-1`. A defensive helper (return whole DN
   when no comma is present) would centralize this across rules.

2. `[IMP-OBJ-JOIN]` — The graph SQL inner-joins `dim_object` twice and then
   the enrichment SQL re-queries `dim_object` for every group. A single
   `LEFT JOIN` with `object_class = 'group'` in the main query could carry
   the GUID and DN through, avoiding the second pass. Cross-cutting
   refactor; covered by the existing tag.

3. `[IMP-CYC-CONTEXT]` — **RESOLVED.** `ContextJson` now carries, alongside the
   human-readable `cycle` string, a structured `cycle_sids: [sid, ...]` (the
   representative cycle's SIDs) and `cycle_edges: [[from_sid, to_sid], ...]`
   (the directed groupâ†’member nesting edges, closing edge included), so
   downstream remediation tooling can action the break-hint without re-parsing
   the name string. Derived directly from the existing representative cycle —
   no new graph traversal. Pinned by
   `WhenThreeGroupsFormCycle_ThenSEC052ExposesStructuredCycleContext`.

4. `[IMP-CYC-MULTI-WITNESS]` — **RESOLVED (option b — one finding per SCC + meshedness
   context).** Rather than emitting one finding per simple cycle (whose enumeration
   is exponential in a meshed SCC and would explode finding counts), the rule keeps
   its one-finding-per-SCC shape and adds: `scc_size`, `back_edge_count`
   (`intra-SCC edges âˆ’ scc_size`; 0 for a simple ring, higher the more tangled the
   component — an exact, O(edges) meshedness signal), and a **bounded**
   `alternate_cycles: [[sid, ...], ...]` (additional short cycles harvested from the
   per-anchor-neighbor BFS that already runs, capped at 5) with an
   `alternate_cycles_capped` flag. Pinned by
   `WhenMeshedScc_ThenSEC052ReportsBackEdgesAndAlternateCycles` and
   `WhenTwoGroupsMutuallyNest_ThenSEC052HasNoAlternateCycles`.
