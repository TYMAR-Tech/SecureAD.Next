## 1. Catalog claim (verbatim from `rules.yaml`)

```yaml
- id: SEC-006
  name: "Unexpected Principal can Add Members to Admin Group"
  description: >-
    A principal can add members to privileged groups.
  severity: Critical
  category: GroupMembership
  remediation: >-
    Remove write access to member attribute on privileged groups.
  mitre: T1098.007
  tags: ["group-modification", "tier-zero"]
```

Source: `src/SecureAD.Core/Findings/Rules/rules.yaml` lines 58–67.

## 2. Intended detection (plain English)

A finding must be raised for every captured `AddMember` right (a property-write ACE whose `objectType` GUID is the AD `member` attribute, `bf9679c0-0de6-11d0-a285-00aa003049e2`) whose source principal is **not** a well-known admin/system principal **and** whose target is a privileged group (Domain Admins, Enterprise Admins, Schema Admins, Administrators, etc., either by well-known RID or by being a privileged-group member via the closure table). The rule's threat model is direct group-membership injection — adding the attacker (or a controlled SID) into a privileged group.

### 3.1 Effective SQL (from `EvaluateControlEdgeOnAdminTarget`)

```sql
SELECT e.source_sid, e.target_object_guid, o.distinguished_name, e.edge_id, o.sid AS target_sid
FROM fact_control_edge e
INNER JOIN dim_object o ON e.target_object_guid = o.object_guid
WHERE e.control_type = $type AND e.deny_cancelled = 0
ORDER BY e.source_sid, e.target_object_guid
```

`$type` is bound to `ControlType.AddMember.ToString()` â†’ `"AddMember"`.

### 3.2 Post-SQL filters (in C#)

1. **Admin source skip** — `IsAdminSid(source_sid)` true â†’ row skipped (`RuleEvaluatorHelpers.cs:649`).
2. **Target SID required** — rows where `o.sid IS NULL` are skipped (`RuleEvaluatorHelpers.cs:651-652`).
3. **Target must be privileged** — `IsPrivilegedPrincipal(targetSid, context.PrivilegedSids)` must be true. For SEC-006 the target SID is **the group's own SID** (since the ACE is on the group object itself), so the well-known privileged-group RIDs (-512/-518/-519/etc.) are caught by `IsAdminSid` directly; custom-named privileged groups need to be members of one of those (via the closure table) — note that a *group* SID will only land in `BuildPrivilegedSidSet` if `fact_group_membership_closure` records the parent group as a member of another privileged group (nested admin groups).

### 3.3 AddMember edge derivation (upstream)

`ControlEdgeService.DeriveControlTypes` (`ControlEdgeService.cs:396-412`) emits a `ControlType.AddMember` row **only** when:

- `aceType` is `AccessAllowedObject` (5) or `AccessDeniedObject` (6), AND
- `accessMask` has the `ADS_RIGHT_DS_WRITE_PROP` (`0x20`) bit set, AND
- `objectTypeGuid == "bf9679c0-0de6-11d0-a285-00aa003049e2"` (the `member` attribute schema GUID).

ACEs that confer the same *effective* capability via a broader right (`GenericAll`, `GenericWrite`, `WriteAllProperties`) are mapped to those broad `ControlType`s by capture (never to `ControlType.AddMember`). SEC-006 now matches the full property-write equivalence set against `object_class = 'group'` targets, so these are caught for **all** non-admin sources (`[IMP-CTRL-SCOPE]` resolved — see Â§12.5); SEC-060 additionally catches them for broad sources.

### 3.4 Privileged SID set composition

`BuildPrivilegedSidSet` (`FindingsService.cs:357-399`) populates the set from:

- `fact_group_membership_closure` rows whose `group_sid` ends in one of RIDs `{512, 516, 518, 519, 526, 527}`.
- Exact built-in admin SIDs `S-1-5-32-544`, `S-1-5-32-548`, `S-1-5-32-549`, `S-1-5-32-550`, `S-1-5-32-551`.
- All of `RuleEvaluatorHelpers.PrivilegedSystemSids`.

When the closure table is absent the set falls back to the exact built-ins plus system SIDs only.

## 5. Exclusions (and the reason each is correct)

| Exclusion | Mechanism | Justification |
| --- | --- | --- |
| Deny-cancelled edges | `WHERE e.deny_cancelled = 0` | The right is not effective; flagging it would be a false positive. |
| Well-known admin RIDs as source | `IsAdminSid` via RID check (500, 502, 512, 516, 518, 519, 520, 521, 526, 527) | These principals are expected to manage admin-group membership. |
| Well-known system SIDs as source (`S-1-5-18`, `S-1-5-9`, `S-1-3-0`, `S-1-5-10`, BUILTIN operator groups) | `IsAdminSid` via `PrivilegedSystemSids` | Expected built-ins. |
| Targets with `sid IS NULL` | C# null-check before privileged-principal test | A target without a SID (e.g., container) cannot be a privileged group. |
| Non-privileged target groups | `IsPrivilegedPrincipal(targetSid, context.PrivilegedSids)` must be true | Rule scope is admin-group only; AddMember on a regular group is not a SEC-006 concern. |

Not excluded (intentionally subject to review):

- **Broad principals** (`Everyone`, `Authenticated Users`, `Anonymous`) as the source — `IsAdminSid` returns `false` for these, so they fire SEC-006. SEC-060 also covers broad SIDs; the duplication is acceptable because SEC-006 carries the specific group-injection semantics.
- **Privileged-by-membership** principals as the source — `IsAdminSid` does not consult `PrivilegedSids`, so a custom admin SID transitively in Domain Admins still fires SEC-006 against another privileged group. Documented; see Â§12 (`[IMP-PRIV-MEMB-SRC]`).
- **Target object_class** is **not** checked. An `AddMember` edge whose target is a non-group object (data noise) would still fire if the target SID happens to be in the privileged set. Documented as `[IMP-TGT-CLASS]`; see Â§12.
- **Equivalent rights** (`GenericAll`, `GenericWrite`, `WriteAllProperties`) on a privileged group are **now caught** by SEC-006 (`[IMP-CTRL-SCOPE]` resolved; see Â§12.5). They confer the same membership-modification capability and are matched via `PropertyWriteEquivalents(AddMember)` constrained to `object_class = 'group'`.

## 12. Defects / deferred items

> Improvement tags follow the taxonomy in `docs/rules/IMPROVEMENTS.md`.

1. `[IMP-DEL-OBJ]` **`is_deleted` not filtered.** An `AddMember` edge on a deleted privileged group would still fire. **Status: accepted-with-known-limitation.** Capture upstream is expected to skip tombstoned objects; if a deleted admin group is captured at all, surfacing the finding is preferable to silent suppression.
2. `[IMP-DN-ENRICH]` **`Detail` does not include source or target display name.** Only SIDs and the target DN are rendered. **Status: accepted-with-known-limitation.** Identical to SEC-003/004/005 Â§12.2; shared resolution.
3. `[IMP-PRIV-MEMB-SRC]` **Privileged-by-membership not excluded as source** (see E8). **Status: accepted-with-known-limitation.** Identical to SEC-003/004/005 Â§12.3; shared resolution.
4. `[IMP-PRIV-PROV]` **No privileged-group provenance in `ContextJson`.** For SEC-006 the "privileged" qualifier means either a well-known RID (no provenance needed) or closure-membership (the closure parent SIDs would be informative). **Status: deferred improvement.** Identical to SEC-003/004/005 Â§12.4; a single `RuleEvaluationContext.PrivilegedSidProvenance` refactor resolves all four rules at once.
5. `[IMP-CTRL-SCOPE]` **RESOLVED — proof-of-shape for the widening group.** `GenericAll` / `GenericWrite` / `WriteAllProperties` on a privileged group all permit membership injection but capture tags each ACE with exactly one `ControlType` (and never decomposes `GenericAll`), so SEC-006 keyed on the literal `AddMember` edge missed them. SEC-006 now dispatches the property-write equivalence set `RuleEvaluatorHelpers.PropertyWriteEquivalents(AddMember)` = `{AddMember, GenericAll, GenericWrite, WriteAllProperties}` via the new class-filtered `EvaluateControlEdgeOnAdminTarget` overload. DACL-pivot rights (`WriteDacl` / `WriteOwner` / `Owns`) intentionally excluded — they remain SEC-004 / SEC-005's domain (preserved by `WhenWriteDaclOnPrivilegedGroup_ThenSEC006DoesNotFire`). Pin `WhenGenericWriteOnPrivilegedGroup_ThenSEC006Fires` flipped to `..._ThenSEC006Fires`; added `GenericAll` / `WriteAllProperties` positives and a multi-edge-collapse test.
6. `[IMP-TGT-CLASS]` **RESOLVED (coupled with `[IMP-CTRL-SCOPE]`).** The broad rights in the set are class-agnostic, so widening without a class filter would fire "can add members" on a privileged non-group target (e.g. a `GenericAll` edge on the built-in Administrator user). The new overload takes a `targetObjectClass` argument; SEC-006 passes `'group'`. Pinned by `WhenGenericAllOnPrivilegedUserNotGroup_ThenSEC006DoesNotFire`. This is the general mechanism for the `[IMP-CTRL-SCOPE]` widening group — the class filter is mandatory, not optional.
