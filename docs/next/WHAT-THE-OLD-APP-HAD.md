# What the old app had

One row per component in [`docs/map/`](../map/README.md) - 256 of them, A1 through K27, generated
from the map's component headings rather than typed.

**This is an inventory of the predecessor, and nothing in it is owed by anybody.** It records what
the old application had, so that a session picking up a subject can find every piece of the old app
that touched it without reading all 256 rows. It is research material. What the new product will
build is decided in [`docs/areas/`](../areas/README.md) and in the records those area files cite,
never here.

Until 2026-08-16 each row also carried a disposition, a target project, a status and a documentation
obligation, and read as a plan being worked through. That plan is not how the work is done: a
subject is chosen, the old app's documentation is read as research, and the decision is recorded in
the area file. Those four columns are gone, and with them every reading of this file as a list of
outstanding work.

| Column | Content |
|---|---|
| **Component** | The map ID |
| **Map says** | The component name in the map, linked to its branch file |
| **Addresses** | What is known about this subject: the records that govern it, what the predecessor did, what has been built, and any findings raised against it |
| **Area** | The area file in [`docs/areas/`](../areas/README.md) that owns this subject, or `&mdash; removed` where the capability was decided against. **`?` means nobody has judged it yet** |

**The Area column is where the row is discussed, not a promise that it will be built.** A row tagged
`how-compare-works` says only that compare is the conversation this subject belongs to. Whether the
subject is built at all is settled in that area file and its records, never here.

The table below sits between the two markers around it. The tests in
`next/tests/SecureAD.Next.Tests/Inventory/` parse only what lies between them, so the rows after the
end marker - which are not map components - do not have to pretend to be.
